# 暴力匹配与 KMP（同一个返回语句，一个对一个是错的）

> 对应程序：[ViolenceMatch.java](./ViolenceMatch.java)、[KMPAlgorithm.java](./KMPAlgorithm.java)
> 同一个任务：在主串里找子串，返回起始下标，找不到返回 -1。
> 两份代码放在一起正好是一份对照 —— **KMP 那份是对的，暴力那份的 return 写错了。**

---

## 一、先说结论：`ViolenceMatch` 的 `main` 打印 `index = 3`，但正确答案是 2

```
text    = "hello txf, thank you"
pattern = "ll"
String.indexOf("ll") -> 2
violenceMatch(...)   -> 3        ← 程序原样打印出来的就是 3
```

不是偶发。固定种子造 20 万组随机串（主串 1..20 字符、模式串 1..4 字符，字母表只有 a/b/c，保证大量命中），
把 `violenceMatch` 的结果和 `String.indexOf` 逐一比对，只统计**确实存在匹配**的那 92,256 组：

| 结果 | 次数 |
| --- | --- |
| 与 `indexOf` 完全一致 | **0** |
| 恰好比 `indexOf` 大 1 | **92,256** |
| 说"不存在"（漏答） | 0 |
| 返回别的错下标 | 0 |

**每一次都恰好大 1。** 同一批数据上 `kmpSearch` 与 `indexOf` 比对：**20 万组全部一致，0 次分歧、0 次误报**。

问题出在最后那行：

```java
if (j == s2Len) return i - j + 1;   // ViolenceMatch
if (j == str2.length()) return i - j + 1;   // KMPAlgorithm —— 同样写法，这里是对的
```

两行长得一样，`i` 的含义却不同：

```
   暴力匹配：匹配上时执行 i++; j++  → 循环退出时 i 已经指到"匹配段后面的那一个字符"
             起始 = i - j          写成 i - j + 1 就多走了一格
   KMP：     for (int i = 0; ...) 里 i 是"刚刚比过的那个字符"，匹配段最后一位就是 i
             起始 = i - j + 1      这个 +1 才是必要的
```

**一句话：`+1` 补偿的是"i 指在最后一个匹配字符上"，暴力版的 `i` 指在下一个字符上，本来就无需补偿。**
顺带一提，`else` 分支里那句 `i = i - j + 1;` 是**对的** —— 那里回溯要退到"本次起点的下一个字符"，
这个正确的 `+1` 和最后 return 里那个错误的 `+1` 长得一样，很容易误以为两处都该改。

## 二、几个手算样例，把 off-by-one 钉死

| 输入 | `indexOf` | `violenceMatch` |
| --- | --- | --- |
| `"abc"` 找 `"a"` | 0 | **1** |
| `"abc"` 找 `"abc"` | 0 | **1** |

| `"abc"` 找 `"z"` | -1 | -1 |
| `"abc"` 找 `""` | 0 | **1** |

空模式串返回 1（正确是 0），也顺带暴露了它没做任何长度校验 —— 不过因为 `while (j < s2Len)` 一进来就不成立，

## 三、KMP 那份的两个 `main` 输出都对

```
[0, 0, 0, 0, 1, 2, 0]      ← next 数组
index = 15                 ← 与 "BBC ABCDAB ABCDABCDABDE".indexOf("ABCDABD") == 15 一致
```

代码注释里写的 `[0, 0, 0, 0, 1, 2, 0]` 和实跑一致。几组 next 表（同一份 `kmpNext`）：

| 模式串 | next |
| --- | --- |
| `A` | `[0]` |
| `AB` | `[0, 0]` |
| `ABCDABD` | `[0, 0, 0, 0, 1, 2, 0]` |
| `AAAA` | `[0, 1, 2, 3]` |
| `ABABA` | `[0, 0, 1, 2, 3]` |
| `ABCABCABCA` | `[0, 0, 0, 1, 2, 3, 4, 5, 6, 7]` |
| `AAABAAA` | `[0, 1, 2, 0, 1, 2, 3]` |

`AAAA` 是 `[0,1,2,3]` 这种"一路涨"的形状，正是最坏情况的来源；`AAABAAA` 中间那个 0 是第四个字符 `B` 打断了前缀。

**但 `kmpNext("")` 会当场抛异常**：

```
java.lang.ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0
```

因为方法第一句就是 `next[0] = 0`，而空串建出来的是 `new int[0]`。
调用顺序也是坑：`kmpSearch(str1, "", next)` 里 `str2.charAt(0)` 同样会炸，
只是 `kmpNext` 先炸所以看不到它。**空模式串这条路这两份代码都没挡。**

## 四、KMP 到底省了多少次比较（实测比较次数，不是耗时）

先跑他自己 `main` 里那组数据（主串 23 字符、模式串 7 字符）：

```
暴力匹配 36 次字符比较
KMP      25 次（搜索） + 7 次（建 next 表） = 32 次
```

**只差 4 次。** 这组数据看不出 KMP 的好处 —— 因为 `ABCDABD` 里重复的部分太少，暴力匹配也没怎么白比。
换成"部分匹配反复失败"的形状就完全不同了。构造 `text = A^n + B`、`pat = A^(n/2) + B`（每次都要比到最后一位才发现不匹配），
实测比较次数：

| text | pat | 暴力 | KMP 搜索 | KMP 建表 |
| --- | --- | --- | --- | --- |
| `AAAAB` | `AAB` | 9 | 7 | 3 |
| `AAAAAAB` | `AAAB` | 16 | 10 | 5 |
| `AAAAAAAAB` | `AAAAB` | 25 | 13 | 7 |
| `AAAAAAAAAAB` | `AAAAAB` | 36 | 16 | 9 |
| `AAAA…AB`（11 个 A） | `AAAAAAB` | 49 | 19 | 11 |
| `AAAA…AB`（22 个 A） | `AAAAAAAAAAAB` | **144** | **34** | 21 |

规律很清楚：暴力的次数是 `|pat|²`（模式串长度平方），KMP 是 `3k+1`（随主串长度线性、与模式串几乎无关）。

规模化到 100 万字符：

```
text = 1,000,000 个 A + B      pat = 10 个 A + B
暴力匹配  10,999,901 次比较  → 9 ms
KMP        1,999,991 + 19 次 = 2,000,010 比较 → 3 ms
indexOf    0 ms
```

再来一个"根本不存在"的例子（主串 `ABABAB…AB` 32 字符，模式串 `ABABABCD`）：暴力 110 次，KMP 45 + 建表 9 = 54 次。

**这三组数字要分开看：** 比较次数差了 5.5 倍，墙钟时间只差 3 倍，而 `indexOf` 直接就是 0 ms。
原因是这两份 Java 代码每轮循环都调 `str.charAt(i)`（一次带边界检查的方法调用），
KMP 省下的"重复比较"被方法调用和分支开销吃掉了一大半。**教学意义上的复杂度差别是真的，
工程意义上的常数也在同一量级** —— 真要跑生产，用 `String.indexOf`，它内部是优化过的。

## 五、两份代码都只返回第一个匹配

```
text = ABABABABAB   pattern = ABAB
kmpSearch -> 0
实际所有出现位置 -> [0, 2, 4, 6]
```

`kmpSearch` 里 `if (j == str2.length()) return ...` 直接返回，所以后面的 3 个位置永远不会被找到。
要找全部出现，得在命中后不返回、而是 `j = next[j - 1]` 继续走 ——
**注意是 `next[j-1]` 而不是 `j = 0`**，因为重叠的部分可以复用（这正是 KMP 的全部精髓）。

## 六、暴力匹配的回溯为什么"不亏本"却仍然输

暴力的 `i = i - j + 1` 把主串指针退回到"本次起点的下一个字符"，看起来只是白比了 `j` 次。
但最坏情况是每前进一个起点就白比整个模式串长度，于是 `|text| × |pat|`。
`AAAA…AB` 那种输入正好把这件事逼到极限：每次都比到最后一位才失败。

KMP 的做法是**失败时不退回主串指针**，只退模式串指针 `j = next[j - 1]`：
`i` 永远单向前进（`for (int i = 0; ...; i++)`），所以主串最多被扫一遍，
代价全在"模式串自己退几步"，而这几步的总次数被 `next` 表压成了线性。

```
   暴力：主串指针来回退，重复比较
   KMP ：主串指针一动不动，只把模式串往前滑 —— 滑多少由 next 表决定
```

这也是为什么第四节实测里 KMP 的比较次数几乎不随主串长度里的"A 数量"暴涨。

## 七、这两份代码放在一起的意义

一份**功能正确、效率低**（KMP），一份**效率符合预期、结果错**（暴力）。
把它们的 `return` 并排看是最值得记住的一处：

```java
// ViolenceMatch：i 在退出循环时已经是"匹配段之后"
if (j == s2Len) return i - j;        // 正确写法

// KMPAlgorithm：i 停在"匹配段最后一位"
if (j == str2.length()) return i - j + 1;   // 已经是正确写法
```

修的时候只改暴力那一处。另外两处（模式串长度 0、`kmpNext("")` 会抛异常）如果要把它们当工具方法用，
也得在入口挡一下 —— 不过按题面/课堂用法（模式串是固定字面量），这两处都触发不到。
