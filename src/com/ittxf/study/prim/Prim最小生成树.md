# Prim 最小生成树（`h1/h2` 忘了复位，出错时打印的是上一轮的边）

> 对应程序：[PrimAlgorithm.java](./PrimAlgorithm.java)（同一文件里还有 `MiniSpanTree` 和 `Graph` 两个类）
> 7 个顶点 A..G、10 条边（邻接矩阵上三角数出来），从 A 出发求最小生成树。
> 思路：`visited[]` 分成"已进树"和"没进树"两堆，每轮在所有跨堆的边里挑权值最小的一条，把对面那个点拉进来。

---

## 一、`main` 的实际输出

```
   ∞   5   7   ∞   ∞   ∞   2
   5   ∞   ∞   9   ∞   ∞   3
   7   ∞   ∞   ∞   8   ∞   ∞
   ∞   9   ∞   ∞   ∞   4   ∞
   ∞   ∞   8   ∞   ∞   5   4
   ∞   ∞   ∞   4   5   ∞   6
   2   3   ∞   ∞   4   6   ∞
边< A, G > 权值：2
边< G, B > 权值：3
边< G, E > 权值：4
边< E, F > 权值：5
边< F, D > 权值：4
边< A, C > 权值：7
最小生成树的总权值为：25
```

拿一份独立实现（同一张矩阵、同样把 10000 当无边，但每次都正确地重置候选）逐条对照：**总权值 25，一致**。
而且**从 7 个不同起点分别跑，两份实现每次都给出 25**：

```
start=A his=25 ref=25 | start=B 25/25 | C 25/25 | D 25/25 | E 25/25 | F 25/25 | G 25/25
```

（最小生成树的权值本来就和起点无关，这里正好把这条性质验证了一遍。）

## 二、`prim()` 的三重循环在干什么

```java
for (int k = 1; k < graph.vertexCount; k++) {              // 要选 V-1 条边
    for (int i = 0; i < graph.vertexCount; i++)            // 扫全部行
        for (int j = 0; j < graph.vertexCount; j++)        // 扫全部列
            if (visited[i] == 1 && visited[j] == 0 && graph.adjMatrix[i][j] < miniWeight) { ... }
    System.out.println("边< " + graph.data[h1] + ", " + graph.data[h2] + " > 权值：" + miniWeight);
    visited[h2] = 1;
    totalWeight += miniWeight;
    miniWeight = 10000;                                     // 每轮重置
}
```

三件事值得单拎出来：

1. **循环次数是 `V-1`**，因为生成树正好 `V-1` 条边。第 V 个点被拉进来时循环就结束了，所以 `start` 那个点永远不会出现在 `h2` 上。
2. **`i`/`j` 都从 0 扫到 V-1**，用 `visited[i]==1 && visited[j]==0` 现场筛"跨堆"的边。
   也就是说每一轮都无条件把整张 `V×V` 矩阵读一遍，而不是只读"已选点 × 未选点"那一块。
3. **`miniWeight` 每轮重置回 10000，但 `h1`/`h2` 没有重置** —— 第五节那些奇怪输出全是从这一句来的。

## 三、`10000` 是"无穷大"，这个约定有多脆

判断写的是 `graph.adjMatrix[i][j] < miniWeight`，而 `miniWeight` 每轮被重置成 `10000`。
于是**权值 ≥ 10000 的边永远不可能被选中**，等于不存在。构造一张"必须走一条 20000 的边才能连通"的图：

```
A-B = 20000（A 唯一的一条边）、B-C = 1、C-D = 2，从 D 出发
本程序输出：
   边< D, C > 权值：2
   边< C, B > 权值：1
   边< C, B > 权值：10000          ← 这一条是假的
   总权值 10003
真实最小生成树 = 20000 + 1 + 2 = 20003
```

两处同时出错：`A` 根本没被连进来，而打印的那行是 `<C, B>`（上一轮的边）配一个 10000 的权值。
**把"无边"和"很贵的边"用同一个数字表示，代价就是这两种情况在代码里长得不一样、后果却混在一起。**
（对照：Kruskal 那份用 `Integer.MAX_VALUE` 表示 INF，同样的手法但没人家的数据够不到，见 Kruskal 笔记第五节。）

## 四、图不连通时会打印一条权值 10000 的假边

`h1/h2` 不复用重置 + `miniWeight` 重置成 10000，组合出的失败模式很具体。
构造一张 D 孤立的图（A-B=1、A-C=3）：

```
本程序（从 A）：                     参考实现：
   边< A, B > 权值：1                   -1（不连通，压根没有生成树）
   边< A, C > 权值：3
   边< A, C > 权值：10000    ← 上一轮的边，权值被顶成 10000
   总权值 10004
```

第三轮里 `A,B,C` 都已 `visited`，`visited[i]==1 && visited[j]==0` 一次都不成立，
所以 `miniWeight` 停在 10000、`h1/h2` 停在上一轮的 `A,C` —— 程序于是"复述"了上一条边，
再给它的总权值加上一个 10000。**输出格式完全正常，没有任何异常，只有数字是编的。**

## 五、有向/不对称矩阵：Prim 只认"从已选指向未选"的那一半

矩阵只在下三角填了边（`B→A = 5`、`C→B = 7`，上三角全是 10000）：

```
本程序从 A 出发：
   边< A, A > 权值：10000
   边< A, A > 权值：10000
   总权值 20000
```

`h1 == h2 == A` 就是第四节的"初始值原样打印"（一轮都没找到候选，`h1/h2` 还停在 `start`）。
原因是判断只走 `visited[i]==1 && visited[j]==0` 的 `adjMatrix[i][j]` —— 也就是**只看"已选→未选"方向**。
无向图必须把矩阵填成对称的，这份代码不会检查，只会安静地给出 20000 这种一眼该起疑的数字。

（同一张不对称矩阵交给 Kruskal 那份程序，`getEdges()` 只扫上三角，结果是一条边都找不到。两份实现"漏"的方向正好相反，见 Kruskal 笔记第四节。）

## 六、代价：每轮把整张矩阵读一遍，所以是 O(V³)

`V-1` 轮 × 每轮 `V²` 次判断。实测（每张图都保证连通，权值随机，同时跑第四节的参考实现核对总权值）：

| V | 边数 | 本程序耗时 | 总权值 | 与参考实现一致 |
| --- | --- | --- | --- | --- |
| 100 | 387 | 2 ms | 146,633 | 是 |
| 200 | 785 | 6 ms | 291,539 | 是 |
| 300 | 1,178 | 5 ms | 427,248 | 是 |
| 400 | 1,585 | 13 ms | 569,230 | 是 |
| 500 | 1,983 | 25 ms | 737,149 | 是 |
| 600 | 2,385 | **45 ms** | 958,847 | 是 |

V 从 300 到 600（翻倍）时间从 5ms 到 45ms（约 9 倍），符合 `V³` 而不是 `V²` 或 `V²log V`。
V=600 时那一轮要判断 600×600 = 36 万个格子、总共约 2.15 亿次 —— 而**边只有 2,385 条**。

同一批数据上 Kruskal 那份的主循环（`V-1` 之外的选边判断）是 **0 ms**，取边+排序也是 0~1 ms。
稠密图（边接近平方）上 Prim 这种朴素写法才划算；**稀疏图上"扫全矩阵"就是纯浪费**，
标准解法是给每个未选点维护一条"到已选集合的最短边"（`lowKeys[]`），只用堆更新，降到 O(E log V)。
这份程序没有做那层优化，它是最直白的那种写法。

## 七、`showGraph` 里的两处小地方

- 注释写"普通数字，占 6 个宽度右对齐"，代码是 `System.out.printf("%4d", ...)`，实际占 4 格。
  打出来的矩阵是对的，只是注释和代码不一致。
- `∞` 这个字符要 UTF-8 控制台才不糊：`java -Dstdout.encoding=UTF-8` 才打得出来，
  Windows 默认 GBK 控制台下这里会是一串乱码（本机实测：不加参数时程序输出的是 GBK 字节）。
- `createGraph` 把参数里的 `adjMatrix` **逐格拷进** `Graph` 的矩阵，所以外部数组之后怎么改都不影响图 ——
  这点比 Kruskal 那份做得稳妥（那边也是逐格拷贝，两份一致）。

## 八、一句话记住

```
   V-1 轮、每轮扫整张 V×V 矩阵 → O(V³)，实测 V=600 要判断约 2.15 亿次而图里只有 2,385 条边；
   正确性在这张图上没问题：7 个起点分别跑，总权值都是 25，和参考实现逐一吻合；
   但 miniWeight 复位、h1/h2 不复位 —— 一旦某轮找不到候选（图不连通、有向矩阵填错方向、
   权值 ≥ 10000 被判成无边），它就复述上一轮的边并塞进一个 10000，
   输出格式一切正常，只有数字是编的。
```
