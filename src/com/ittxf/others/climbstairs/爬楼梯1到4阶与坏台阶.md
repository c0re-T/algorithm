# 爬楼梯：一次 1~4 阶 + 坏台阶（四阶斐波那契，2^(n-1) 从第 5 项开始失效）

> 对应程序：[ClimbStairs.java](./ClimbStairs.java)
> `main` 用 n=10、坏台阶 `{3,7}`，实测：
>
> ```
> 81
> ```

---

## 一、状态转移

一次能跨 1、2、3 或 4 阶，所以到第 i 阶的方法数是前四个位置之和：

```java
dp[0] = 1;                                  // 站在地上算一种"到达方式"
for (int i = 1; i <= n; i++) {
    if (isBad[i]) { dp[i] = 0; continue; }  // 坏台阶：不能落脚，方法数归零
    for (int k = 1; k <= 4; k++) {
        if (i - k >= 0) dp[i] = (dp[i] + dp[i - k]) % MOD;
        else break;                         // 再往前就没有台阶了
    }
}
```

`dp[0] = 1` 是整套递推的地基：它代表"一步直接跨到第 k 阶"这一种走法。写成 0 会让所有 dp 值全是 0。

坏台阶的处理是 `dp[i] = 0` 而不是 `continue` 跳过赋值 —— 因为后面还会有 `dp[i+1] += dp[i]`，必须显式留下一个 0。**坏台阶只挡"落脚"，不挡"跨过"**：n=4、bad={2} 实测给 4，四种走法（数字是步长）是 `4`、`1+3`、`3+1`、`1+2+1` —— 最后一种从第 1 阶一步跨 2 到第 3 阶，空中越过第 2 阶但不踩它，合法。

`else break` 而不是 `continue`：k 是递增的，一旦 `i-k < 0`，更大的 k 只会更负，后面全是无效项，直接跳出。写成 continue 结果一样，只是多转几圈。

## 二、没有坏台阶时它是四阶斐波那契

实测 f(1)..f(7)：

```
1, 2, 4, 8, 15, 29, 56
```

前四项正好是 `2^(n-1)`，很容易以为规律就是 2 的幂。**第一次失效在 n=5：f(5)=15 而不是 16。** 原因是从第 5 项起递推式里不再有 `dp[0]` 这一项（`i-k >= 0` 把 k=5 以上挡住了），少了那个常数 1 的补给。前四项之所以像 2 的幂，是因为它们都还能一步从地面跨上来。

## 三、坏台阶的过滤与边界

```java
for (int b : bad) if (b >= 1 && b <= n) isBad[b] = true;
```

这个过滤是必需的，实测：

| 输入 | 结果 |
| --- | --- |
| n=5，bad={0,−3,6,99} | 15（四个全被过滤，等于没有坏台阶） |
| n=10，bad={3,3,3} | 177（重复标记同一个位置，幂等） |
| **去掉过滤**，n=5，bad={6} | `ArrayIndexOutOfBoundsException: Index 6 out of bounds for length 6` |
| 去掉过滤，bad 里有 0 | 15（`isBad[0]` 落在数组内，但循环从 i=1 开始，没人读它） |

也就是说：越界的坏台阶会直接炸，而 0 恰好是"越界但无害"的那一个。过滤把两类都挡住了。

其他边界实测：

| 输入 | 结果 | 说明 |
| --- | --- | --- |
| n=0 | 1 | 循环一次不进，返回 dp[0] |
| n=1，bad={1} | 0 | 顶阶就是坏的，走不到 |
| n=5，bad={5} | 0 | 同上 |
| n=10，bad={5,6,7,8} | 0 | 连续 4 个坏台阶，一步最多跨 4，跨不过去 |
| **n=−1** | `ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0` | `new int[0]` 之后 `dp[0]=1` 越界 |

连续 4 个坏台阶那条是"步长上限"的直接后果：如果允许一次跨 5 阶就能过去。n=−1 没有任何防护，方法开头缺一句 `if (n < 0) return 0`。

20,000 组随机 (n ≤ 15，0..4 个坏台阶)，与"记忆化枚举所有走法"的精确参考对比：


## 四、取模会不会溢出

`MOD = 1_000_000_007`，每步做的是 `(dp[i] + dp[i-k]) % MOD`。两个加数都已经小于 MOD，所以中间结果最大 `2 × (MOD-1) = 2,000,000,012`，而 `Integer.MAX_VALUE = 2,147,483,647` —— **还差 1.47 亿才溢出，int 够用**。

关键是"每加一次就取一次模"。如果写成先累加四项再取模，最大 `4 × (MOD-1) = 4,000,000,024`，超过 int 上限，会静默溢出成负数。当前这份的写法是安全的。

实测：

| n（无坏台阶） | 结果 | 耗时 |
| --- | --- | --- |
| 100 | 500369454 | 0 ms |
| 100,000 | 472399532 | 1 ms |
| 1,000,000 | 847588428 | 13 ms |

`O(4n)` 时间、`O(n)` 空间。空间还能压到 `O(1)`（只留最近 4 个 dp 值），但坏台阶数组仍需 `O(n)`，除非改成用 Set 存坏台阶。

## 五、一句话记住

```
   dp[i] = dp[i-1] + dp[i-2] + dp[i-3] + dp[i-4]，dp[0] = 1；
   坏台阶 dp[i] = 0，只挡落脚不挡跨过（n=4 bad={2} → 4）；
   无坏台阶时 1,2,4,8,15,29,56 —— 2^(n-1) 第一次失效在 n=5；
   b >= 1 && b <= n 的过滤删掉就会 AIOOBE（bad={6}, n=5）；
   n=-1 也 AIOOBE，没挡；n=0 返回 1；连续 4 个坏台阶走不过去；
   每加一次取一次模，中间值最大 2,000,000,012 < int 上限；
   20,000 组与记忆化枚举 0 差异；n=100 万只要 13 ms。
```
