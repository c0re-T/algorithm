# LeetCode 739 每日温度（单调栈存下标）

> 对应程序：[LeetCode739_DailyTemperatures.java](./LeetCode739_DailyTemperatures.java)
> `main` 跑三组示例，实测：
>
> ```
> [1, 1, 4, 2, 1, 1, 0, 0]
> [1, 1, 1, 0]
> [1, 1, 0]
> ```

---

## 一、栈里存下标，温度从栈底到栈顶单调递减

```java
for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && temperatures[i] > temperatures[stack.peek()]) {
        int preIndex = stack.pop();
        res[preIndex] = i - preIndex;
    }
    stack.push(i);
}
```

当前温度比栈顶高，说明栈顶那天终于等到了更暖的一天，弹出并写下 `i - preIndex`。每个下标进栈一次、出栈一次，`O(n)`。栈里存**下标**而不是温度，因为答案要的是天数差。

## 二、`>` 不能写成 `>=`

题面要的是"更高"，相等不算。改成 `>=` 后 20,000 组随机（温度只有 30..35，大量相等）：

| 版本 | 差异 |
| --- | --- |
| 原版 `>` | **0** |
| `>=` | **18,460 / 20,000** |

最小例子 `{70,70}`：原版 `[0,0]`，`>=` 版会让第二天把第一天弹掉并记 1。

## 三、对拍与边界

20,000 组随机（长度 0..59、温度 30..35）与 `O(n²)` 暴力：

```
20,000 组：0 差异
```

| 输入 | 结果 |
| --- | --- |
| `{}` | `[]` |
| `{50}` | `[0]` |
| 严格递减 `{90,80,70,60}` | `[0,0,0,0]`（栈里压满，最后一起留在栈里） |
| `{70,70}` | `[0,0]` |
| `null` | `NullPointerException: Cannot read the array length` |

入参只读，同一数组连调两次结果一致。

## 四、注释里的暴力版

注释版双重循环结果也对（5,000 组随机 0 差异），但 n=10,000 时两种写法实测都是 0 ms —— **这个规模测不出复杂度差异**。单调栈在 100,000 上：严格递减 3 ms、严格递增 1 ms、之字形 2 ms；同样规模的暴力要 5×10⁹ 次比较，跑不动。

一个容易忽略的点：全相等的数组不会触发任何弹出，栈会一路压满 n 个下标（实测 10,000 个），但每个下标只进出一次，仍是 O(n)。

## 五、一句话记住

```
   栈存下标、温度单调递减；当前温度 > 栈顶就弹出并写 i - preIndex；
   `>` 写成 `>=` 会错 18,460/20,000（{70,70} 从 [0,0] 变 [1,0]）；
   20,000 组随机与 O(n²) 暴力 0 差异；
   空数组 []、单元素 [0]、严格递减全 0、null NPE、入参只读；
   注释暴力版结果对但 n=1e4 两者都 0 ms，规模不够看不出差别；
   单调栈 1e5 只要 1–3 ms；全相等时栈压满 n 个下标，仍是 O(n)。
```
