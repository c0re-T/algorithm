# LeetCode 45 跳跃游戏 II（贪心分层，走到边界才计步）

> 对应程序：[LeetCode45_JumpGameII.java](./LeetCode45_JumpGameII.java)
> `main` 跑两组示例，实测：
>
> ```
> 2
> 2
> ```

---

## 一、把"最少几步"看成 BFS 分层，但不真的建队列

```java
int maxReach = 0;      // 下一层能覆盖到的最远处
int steps = 0;
int currentEnd = 0;    // 当前这一层的右边界
for (int i = 0; i < nums.length - 1 && i <= maxReach; i++) {
    maxReach = Math.max(maxReach, i + nums[i]);
    if (i == currentEnd) {
        ++steps;
        currentEnd = maxReach;
    }
}
return steps;
```

`[0, currentEnd]` 是"steps 步能到的范围"。扫描这一层时顺手统计下一层的最远处 `maxReach`；**走到层边界才 `++steps`**，把边界推进到 `maxReach`。等价于 BFS 逐层扩展，但只用三个 int，`O(n)` 时间 `O(1)` 空间。

对拍两条：

- 30,000 组随机可达数组（长度 1..30、跳跃力 1..5）与最短路 DP：**0 处差异**
- **穷举**长度 1..7、跳跃力 0..3 的全部 **21,844 个数组**（其中 11,276 个可达）：**0 处差异**

## 二、`i < nums.length - 1` 是必需的

最后一格是终点，站在终点上不需要再起跳。让它进入循环就会多算一步：

| 输入 | 原版 | 改成 `i < n` |
| --- | --- | --- |
| `{3}` | **0** | 1 |
| `{0}` | **0** | 1 |
| `{2,3,1,1,4}` | **2** | 3 |

30,000 组随机里错 **9,236 处**，第一个反例就是单元素 `{3}`。

对照 [LeetCode 55](../p55_jumpgame/LeetCode55-跳跃游戏.md)：同一处上界在那边改成 `i < n` 是**完全等价的**（0 差异），因为 55 只做判断、不在循环体里计数。**同一副贪心骨架，计数版对边界敏感，判断版不敏感。**

## 三、`i <= maxReach` 在这题是可证明多余的

实测：30,000 组随机可达数组 **0 处差异**；穷举里 11,276 个可达数组 **0 处差异**；连 10,568 个**不可达**数组，加不加这个条件返回值也**完全一样**。

原因：一旦 `i > maxReach`，就有 `currentEnd <= maxReach < i`，`i == currentEnd` 永远不成立，`steps` 不再增长，`currentEnd` 也不再推进。后面即使 `maxReach` 被刷新，也影响不到返回值。

**这和 55 题正好相反** —— 那边这个守卫挡掉了 9,806 / 30,000 个错误。留着它无害（也表达了"只在可达格上决策"的意图），但要知道它在这里不承担正确性。

## 四、另两个变体

| 变体 | 差异 | 第一个反例 |
| --- | --- | --- |
| `currentEnd = i + nums[i]`（不用 `maxReach`） | **10,835 / 30,000** | 15 个元素的数组返回 7，应为 5 |
| 把 `if (i == currentEnd)` 挪到 `maxReach` 更新**之前** | **25,980 / 30,000** | `{2,2,1,1,3,4}` 返回 **1**，应为 4 |

第一个错在"当前层的下一层边界"应当取**整层的最大覆盖**，而不是最后站的那一格能跳多远。

第二个错得更彻底：i=0 时 `maxReach` 还是 0，边界立刻被推进到 0，第一步就白算了。**先更新覆盖、再判边界**这个顺序不能换。

## 五、不可达输入会安静地返回一个有限步数

题面保证"总能到达最后一格"，程序没有校验：

| 输入 | 程序返回 | DP 判定 |
| --- | --- | --- |
| `{1,0,1}` | 2 | 不可达 |
| `{0,1}` | 1 | 不可达 |
| `{2,0,0,1}` | 2 | 不可达 |
| `{1,0,0,0}` | 2 | 不可达 |
| `{0,5,5,5}` | 1 | 不可达 |

想知道"能不能到"必须先跑 55 题的判断，45 题的返回值在不可达时没有意义。

## 六、边界与溢出

| 输入 | 结果 |
| --- | --- |
| `{0}` | `0` |
| `{5}` | `0` |
| `{}` | `0`（`length-1 = -1`，循环不执行） |
| `{1,1,1,1}` | `3` |
| `{10,1,1,1}` | `1` |
| `null` | `NullPointerException: Cannot read the array length` |

`i + nums[i]` 溢出会真的改变答案（题面 `nums[i] <= 1000` 时不会发生）：

| 输入 | 程序返回 | DP 真值 |
| --- | --- | --- |
| `{1,MAX,1,1,1}` | 2 | 2（碰巧对） |
| `{2,MAX,1,1,1,1}` | **4** | **2** |
| `{3,MAX,1,1,1,1,1}` | **4** | **2** |
| `{2,MAX,1,1,1,1,1,1}` | **6** | **2** |

`1 + MAX` 溢出成负数后 `maxReach` 卡住，贪心退化成"一格一格挪"，步数被放大。第一行说明**单个反例试不出来不代表安全**。

入参只读，同一数组连调两次结果一致。

## 七、实测代价

| 规模与形态 | 耗时 | 步数 |
| --- | --- | --- |
| n=1e7 全部为 1（最坏步数） | **10 ms** | 9,999,999 |
| n=1e7 全部为 1000 | **4 ms** | 10,000 |
| n=1e5 随机 1..5，贪心 | **0 ms** | 28,968 |
| n=1e5 同数据，最短路 DP | 1 ms | 28,968 |

全 1 是步数最多的形态（每步只能前进一格），n=2/10/100/1000 对应 1/9/99/999 步。

## 八、一句话记住

```
   [0,currentEnd] 是 steps 步的覆盖层，扫层内顺手统计 maxReach，走到边界才 ++steps；
   30,000 组随机 + 穷举 21,844 个数组（11,276 可达）与最短路 DP 全 0 差异；
   上界必须是 i<n-1，改成 i<n 错 9,236/30,000（{3} 从 0 变 1）；55 题同一改动却等价；
   i<=maxReach 在这题可证明多余（穷举 21,844 个数组含 10,568 个不可达，返回值全同），55 题却必需；
   currentEnd 用 i+nums[i] 错 10,835，把边界判断挪到更新之前错 25,980（{2,2,1,1,3,4} 返回 1）；
   不可达输入安静返回有限步数（{1,0,1}→2），要判可达得先跑 55；
   {2,MAX,1,1,1,1} 溢出后返回 4（真值 2），但 {1,MAX,1,1,1} 碰巧还对；
   n=1e7 全 1 用 10 ms / 9,999,999 步，全 1000 用 4 ms / 10,000 步。
```
