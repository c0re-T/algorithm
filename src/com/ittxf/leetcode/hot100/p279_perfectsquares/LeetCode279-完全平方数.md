# LeetCode 279 完全平方数（四平方和定理，把 DP 换成数论）

> 对应程序：[LeetCode279_PerfectSquares.java](./LeetCode279_PerfectSquares.java)
> `main` 跑四组示例，实测：
>
> ```
> 2
> 1
> 3
> 2
> ```

---

## 一、答案只可能是 1、2、3、4

```java
while (n % 4 == 0) n /= 4;
if (n % 8 == 7) return 4;
if (isPerfectSquare(n)) return 1;
for (int i = 1; i * i <= n; i++) {
    if (isPerfectSquare(n - i * i)) return 2;
}
return 3;
```

两条定理撑起了整个程序：

- **拉格朗日四平方和定理**：任何正整数都能写成不超过 4 个平方数之和 → 答案上限是 4。
- **勒让德三平方和定理**：`n = 4^a · (8b + 7)` 形式的数**必须**用 4 个 → 先把 4 的因子除干净，再看余 8 是否为 7。

剩下的判 1（本身是平方数）、判 2（枚举一个平方数看 remainder 是否也是平方数），都不是就返回 3。最坏 `O(√n)`，空间 `O(1)`。

对拍两条独立参考：n=1..20,000 与注释里的 DP 版本 **0 处差异**；n=1..2,000 与 BFS 最短路 **0 处差异**。

n=1..20,000 的答案分布：**1 → 141 个，2 → 5,117 个，3 → 11,411 个，4 → 3,331 个**。

## 二、`while (n % 4 == 0)` 不能删

删掉它，`n % 8 == 7` 就漏掉了带 4 因子的那批数：

| 变体 | 差异 | 第一个反例 |
| --- | --- | --- |
| 删掉 `while (n%4==0) n/=4` | **831 / 20,000** | n=28 返回 **3**，应为 4（28 = 25+1+1+1） |
| 删掉 `if (n%8==7) return 4` | **3,331 / 20,000** | n=7 返回 **3**，应为 4 |

28 % 8 = 4 而不是 7，只有先除掉 4 变成 7 才能命中判定。3,331 正好等于区间内答案为 4 的个数 —— 说明这个判定是**唯一**能产出 4 的出口。

反过来，把 `isPerfectSquare(n)` 提到 `while` 之前是**等价的**（0 / 20,000）：平方数模 8 只能是 0、1、4，永远不会是 7，而且除以 4 不改变"是否平方数"。

## 三、`(int) Math.sqrt(x)` 在 int 全域没有精度问题

```java
private boolean isPerfectSquare(int x) {
    int sqrt = (int) Math.sqrt(x);
    return sqrt * sqrt == x;
}
```

穷举 k=1..46,340（46,340² = 2,147,395,600 是 int 内最大的平方数，46,341² 就溢出了）：

- 对 `k*k` 判"是平方数"：**0 处漏判**
- 对 `k*k - 1` 判"是平方数"：**0 处误判**（唯一命中的是 k=1 → x-1=0，而 0 确实等于 0²）

`Math.sqrt` 是正确舍入的，`k*k` 的平方根恰好是整数 k，强转不会掉到 k-1。**这个写法在 int 范围内是安全的**，不需要 `Math.round` 或二分。

## 四、n=0 会死循环

`while (n % 4 == 0) n /= 4;` 在 n=0 时永远成立（0/4 还是 0）。用守护线程实测：**1,500 ms 后线程仍在运行**。

题面限定 `1 <= n <= 10^4`，碰不到 0；但如果拿它当通用工具函数，这是一个真实的挂死点。

其他越界输入：

| 输入 | 结果 |
| --- | --- |
| n=0 | **死循环** |
| n=-1 | `3` |
| n=-4 | `3` |
| n=Integer.MAX_VALUE | `4` |

负数不会挂：`-1 % 8 == -1`（Java 取余保留符号），不等于 7，一路走到 `return 3`。

## 五、分支频率与实测代价

n=1..100,000 走各分支的次数：

| 出口 | 次数 |
| --- | --- |
| 除 4 循环总轮数 | 33,330 |
| 返回 4 | 16,664 |
| 返回 1 | 316 |
| 返回 2 | 23,712 |
| 返回 3（跑完整个 √n 扫描） | **59,308** |

**近六成输入要走最贵的分支**。最长的一次两平方扫描是 316 轮（n=99,858），在该点连调 1,000 次共 1,522 µs，约 1.5 µs 一次。

和 DP 的对比要分场景，否则很容易得出夸张结论：

| 场景 | 数论版 | DP |
| --- | --- | --- |
| 单点 n=1,000,000 | **0 ms** | 2,599 ms（表占 3 MB） |
| 回答全部 n=1..10,000（DP 表只建一次） | 2 ms | **2 ms**（打平） |
| 回答全部 n=1..100,000（DP 表只建一次） | 58 ms | **14 ms**（DP 更快） |
| 回答全部 n=1..10,000，每个 n 都重建 DP 表 | 6 ms | 8,276 ms |

最后一行是**不公平的比较**，列出来只是为了说明：批量查询时 DP 建一次表就能摊薄成本，此时数论版反而慢 4 倍。**数论版的优势在单次大 n 查询和 O(1) 空间，不在批量。**
