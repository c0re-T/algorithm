# LeetCode 54 螺旋矩阵（两条 `if` 是单行/单列不重复遍历的唯一屏障）

> 对应程序：[LeetCode54_SpiralMatrix.java](./LeetCode54_SpiralMatrix.java)
> `main` 用 `{{1,2,3},{4,5,6},{7,8,9}}`，实测输出 `[1, 2, 3, 6, 9, 8, 7, 4, 5]`。

---

## 一、四个边界 + 两条判断

```java
while (top <= bottom && left <= right) {
    for (j = left..right)   list.add(matrix[top][j]);   top++;      // 上边 →
    for (i = top..bottom)   list.add(matrix[i][right]);  right--;   // 右边 ↓
    if (top <= bottom) { for (j = right..left) list.add(matrix[bottom][j]); bottom--; }  // 下边 ←
    if (left <= right) { for (i = bottom..top) list.add(matrix[i][left]);   left++;   }  // 左边 ↑
}
```

前两条边不用判（进入循环时 `top <= bottom`、`left <= right` 已经保证至少一格），
**后两条边必须判**，因为前两条边走完之后边界可能已经交叉了。

实测把这两条 `if` 去掉（其余不变）：

| 矩阵 | 带判断 | 不带判断 |
| --- | --- | --- |
| `[[1,2,3,4]]`（1×4） | `[1,2,3,4]` ✓ | `[1,2,3,4,3,2,1]` ✗ 下边重复一遍 |
| `[[1],[2],[3],[4]]`（4×1） | `[1,2,3,4]` ✓ | `[1,2,3,4,3,2]` ✗ 左边重复一遍 |
| `[[1,2],[3,4]]`（2×2） | `[1,2,4,3]` ✓ | `[1,2,4,3]` ✓ |
| `[[1]]`（1×1） | `[1]` ✓ | `[1]` ✓ |

也就是说：**这两条判断只在"某一边只有一行/一列"时才起作用**，而 2×2、3×3 这种"看起来最典型"的测试数据恰好测不出来。
1×4 和 4×1 才是这个 bug 的探针。

## 二、差分对拍

固定种子 20,000 组随机（行 1..5、列 1..5，元素随机），与"按方向数组 + `visited` 走迷宫"的参考实现比：

```
   不同 —— 0 组
```

参考实现是"右→下→左→上 转圈、撞墙或撞已访问就转向"，和边界法是完全不同的思路，两边一致说明边界推对了。

## 三、边界与代价

```
   m×1 / 1×n / 1×1 / 2×2  -> 见上表，都正确
   空矩阵 new int[][]{}    -> ArrayIndexOutOfBoundsException（matrix[0].length）
   一行零列 new int[1][0]  -> [] （right = -1，循环条件不成立）
```

时间 `O(m·n)`（每个格子恰好进 `list` 一次），额外空间 `O(1)`（不算输出）。
如果把 `list` 换成直接打印，内存就是严格 `O(1)`。

## 四、和 48/73/240 的对照

| 题 | 边界怎么用 |
| --- | --- |
| 54 螺旋 | 四条边界**收缩**，向里走 |
| 48 旋转 | 不需要边界，靠转置 + 行反转 |
| 73 置零 | 只按行/列标记，没有"走"的概念 |
| 240 搜索 | 只用左下角这一个点，做"阶梯式"移动 |

四份代码都以 `matrix[0].length` 取列数，所以**空矩阵（零行）全都会崩** —— 这是这批矩阵题共同的隐含前提。

## 五、一句话记住

```
   上边和右边不用判断（循环条件已保证），下边和左边必须判断 —— 去掉后 1×4 会变成 [1,2,3,4,3,2,1]，
   而 2×2、3×3 测不出来，必须拿单行/单列当探针；
   20,000 组与"方向数组 + visited"参考实现 0 差异；
   O(m·n) 时间、O(1) 额外空间；空矩阵会在 matrix[0].length 处 AIOOBE。
```
