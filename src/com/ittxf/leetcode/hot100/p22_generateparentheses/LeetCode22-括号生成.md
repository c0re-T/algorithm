# LeetCode 22 括号生成（回溯：两个计数器就是全部约束）

> 对应程序：[LeetCode22_GenerateParentheses.java](./LeetCode22_GenerateParentheses.java)
> `main` 传的是 `n = 3`，实测：
>
> ```
> [((())), (()()), (())(), ()(()), ()()()]
> ```

---

## 一、两条约束，一行一条

```java
if (open < n)   { ... 追加 '(' ... }   // 左括号还没用满
if (close < open) { ... 追加 ')' ... }  // 右括号不能多于左括号
```

只要这两条同时成立，生成出来的串**一定合法**，不需要事后校验。`main` 的 `n=3` 实测 5 条，与第 3 个 Catalan 数一致，逐条检查前缀平衡全部通过。

`track.length() == n * 2` 是唯一的触底条件。`open` 和 `close` 不相等时也可能 `length == 2n` 吗？不会 —— `open ≤ n` 且 `close ≤ open`，凑满 `2n` 时必然 `open == close == n`。

## 二、`close < open` 改成 `close < n` 会怎样

这是最容易写错的一处（把"右括号不能超过左括号"记成"右括号不能用超总数"）：

| n | 原版 | `close < n` | 其中非法 | `close` 分支完全不加限制 | 其中非法 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 条 | **2 条** | 1 | **3 条** | 2 |
| 2 | 2 条 | **6 条** | 4 | **11 条** | 9 |
| 3 | 5 条 | **20 条** | 15 | **42 条** | 37 |

`n = 3` 时会生成 `())` 开头这种前缀就已经不平衡的串。**条数变多、每一条都"看起来是括号串"**，只有逐个检查前缀平衡才能发现 —— 这是回溯题里最常见的静默错误形态。

## 三、忘记撤销：五条塌成一条

```java
backtrack(res, track.append("("), n, open + 1, close);
track.deleteCharAt(track.length() - 1);   // 删掉这一行
```

实测：

```
n=3 原版  = [((())), (()()), (())(), ()(()), ()()()]
n=3 忘撤销= [((()))]
```

原因不只是"串越来越长"：`track` 只有一份，而且从不缩短，所以 `track.length() == n * 2` 这个触底条件在整棵树里**只会被满足一次**（长度一旦超过 `2n` 就再也回不去）。于是 `res` 里只有第一条走到底的串。`n=1` 时它恰好是对的（只有一条路径），`n≥2` 全错。

## 四、`n = 0` 返回 `[""]`，打印出来是 `[]`

```
n=0 的 size = 1，元素是空串 = true，直接打印 = []
n=-1 的 size = 0，直接打印 = []
```

两者屏幕上一模一样。`n = 0` 走进"长度为 0 == `n*2` == 0"的触底，把空串存了进去；`n = -1` 时 `0 == -2` 不成立、`open < n` 和 `close < open` 也都不成立，返回真正的空列表。

题面 `1 ≤ n ≤ 8`，两种都触发不到。但"打印一样、`size()` 不一样"这件事值得记——只靠 `main` 的输出看不出区别。

## 五、边界与随机对拍

| 输入 | 结果 |
| --- | --- |
| `n = 0` | 1 条空串（打印 `[]`） |
| `n = -1` | 0 条 |
| `n = 1` / 2 / 3 / 4 / 5 | 1 / 2 / 5 / 14 / 42 条 |

`n = 0..10` 逐档与 Catalan 数对比、逐条检查平衡、查重复、查是否字典序：

```
n=0..10: 条数全部等于 Catalan(n)，非法 0 条，重复 0 条，字典序 true
```

再与"Catalan 递推参考"（`gen(n) = "(" + gen(i) + ")" + gen(n-1-i)`，另一种构造方式）按集合比对，`n = 0..8` 全部一致。输出恰好是字典序，因为 `'(' < ')'` 且 `'('` 分支在前。

同一实例连调三次给 `5 → 1 → 5`，`res` 是局部变量，没有累积问题。

## 六、规模：输出条数 = Catalan(n)

| n | 条数 | 耗时 |
| --- | --- | --- |
| 8 | 1,430 | 0 ms |
| 10 | 16,796 | 1 ms |
| 12 | 208,012 | 13 ms |
| 14 | 2,674,440 | 125 ms |
| 15 | 9,694,845 | 511 ms |
| **16** | **35,357,670** | **`OutOfMemoryError: Java heap space`**（`-Xmx2g`） |

递归深度是 `2n`（n=16 才 32 层），栈完全不是问题；堆先倒。题面 `n ≤ 8`，最多 1,430 条。

## 七、一句话记住

```
   open < n 管左括号不超编，close < open 管右括号不超前 —— 两条就够，不用事后校验；
   把 close < open 写成 close < n：n=1/2/3 分别从 1/2/5 条涨到 2/6/20 条，非法 1/4/15；
   完全去掉 close 的限制：3/11/42 条，非法 2/9/37；
   忘撤销 deleteCharAt：track 只会达到 n*2 一次，五条塌成 [((()))]，n=1 时巧合正确；
   n=0 返回 1 条空串，n=-1 返回 0 条，打印出来都是 []，只有 size() 能区分；
   0..10 条数全等于 Catalan(n)，非法/重复/乱序各 0；与 Catalan 递推参考 0..8 全等；
   深度 2n 不吃栈，n=16 时 3,535 万条 OOM —— 瓶颈是输出条数。
```
