## 一、`'#'` 标记 + 逐层归还，棋盘原样还给调用方

```java
char temp = board[i][j];
board[i][j] = '#';                    // 借用调用方的格子做 visited
boolean found = backtrack(board, word, index + 1, i + 1, j) || ... ;
board[i][j] = temp;                   // 每条 return 路径上都执行
return found;
```

`||` 短路只影响"还要不要继续试下一个方向"，不影响归还 —— `found` 先算出来，然后无条件写回 `temp`。实测：

```
第一次 true  后一致 = true
第二次 false 后仍然一致 = true
```

这是它和 `p200`（把陆地永久抹成 `'0'`）、`p994`（把新鲜橘子永久改成 `2`）最大的区别：那两份把入参改坏了，这份**借了还**。对比写在 README 的坑表里。

注意 `'#'` 是硬编码的哨兵：棋盘本身就含 `'#'` 时，一张 `{{'#','A'}}`（1 行 2 列）找 `"#A"` 实测仍然 `true`（先匹配成功才标记），找 `"A"` 也 `true`。真正会出问题的是词里同时出现 `'#'` 且需要跨越同一格两次 —— 题面保证只有大小写字母，碰不到。

## 二、三个提前返回共同决定正确性

| 位置 | 作用 |
| --- | --- |
| `word == null \|\| word.length() == 0` → `true` | 空词不搜，直接算找到 |
| `board[i][j] != word[index]` → `false` | 字符不符立刻回头 |
| `index == word.length() - 1` → `true` | 最后一个字符也匹配上了，不必再标记 |
| `exist` 里的 `board[i][j] == words[0]` 预筛 | 首字母不符的起点**连递归都不进** |

第四行是纯优化，不影响正确性。它的价值在"大面积不匹配"时：200×200 全 `'Z'`、只有 `(0,0)` 是 `'A'`，找 `"AB"` 实测 **0 ms** —— 4 万个格子里只有 1 个进了递归。

`word == null` 判了，`board == null` 没判：

| 输入 | 结果 |
| --- | --- |
| `word = ""` / `null` | `true` |
| `board = null` | `NullPointerException: Cannot read the array length because "<parameter1>" is null` |
| `board = new char[0][]` | `false`（外层循环 0 次） |
| `board = new char[1][0]` / `new char[3][0]` | `false`（内层 `length` 是 0） |
| 词比格子多（2 格找 3 字） | `false` |
| 大小写不同（`'a'` 找 `"A"`） | `false` |

0 行 / 0 列都不崩，因为 `board[0].length` 写在**循环体里**，行数 0 时根本不会求值。这一点比 `p200` / `p994` 强（那两份在方法第一行就无条件读 `grid[0].length`）。

**锯齿矩阵会崩**：`{{'A','B'},{'C'}}` 找 `"ABC"` → `ArrayIndexOutOfBoundsException: Index 1 out of bounds for length 1`。列数统一用 `board[0].length`，题面保证矩形。

```
差异 = 0
```

把 `visited` 从"改数组"换成"改棋盘上的 `'#'`"，两种完全不同的 visited 载体给出同样的答案，说明标记与归还的时机没写歪。

## 四、递归深度 = 单词长度，题面之外才爆栈

`backtrack` 每匹配一个字符递归一层，所以深度等于词长。用真正的单条蛇形长路径（偶数行整行填满、奇数行只留一个连接格、连接列左右交替）逐档加长：

| 棋盘 | 路径长度 | 结果 |
| --- | --- | --- |
| 100×100 | 5,050 | `true`，0 ms |
| 108×108 | 5,886 | `true` |
| 110×110 | 6,105 | `true` |
| 115×115 | 6,727 | `true` |
| **120×120** | **7,260** | **`StackOverflowError`** |
| 140×140 | 9,870 | `StackOverflowError` |
| 200×200 | 20,100 | `StackOverflowError` |
| 300×300 | 45,150 | `StackOverflowError` |

同一个 200×200 / 300×300 棋盘换成**显式栈的迭代 DFS**（栈里存 `(i, j, 匹配到第几个字符, 下一个方向)`）：20,100 字 **6 ms**、45,150 字 **3 ms**，都能过。

所以爆栈线在 **6,727 和 7,260 层之间**。题面 `m, n ≤ 6`、词长 ≤ 15，深度最多 15 层 —— **这份的爆栈问题只在题面之外存在**，和 `p200`（题面 300×300 正好落在爆栈区间）不一样。

## 五、最坏耗时：`'#'` 只省空间，不省时间

10×10 全 `'A'` 的棋盘，找 `k` 个 `A` 再接一个不存在的 `B` —— 必须搜遍所有长度为 `k` 的简单路径才能判定失败：

| k | 耗时 | 相对上一档 |
| --- | --- | --- |
| 4 | 37 µs | — |
| 5 | 100 µs | 2.7× |
| 6 | 255 µs | 2.6× |
| 7 | 625 µs | 2.5× |
| 8 | 1,551 µs | 2.5× |
| 9 | 3,896 µs | 2.5× |

每多一个字符大约乘 2.5，指数增长。100 格棋盘上每格最多 4 个方向，理论上界是 4^k 量级，实际因为不能回头和出界压到 2.5 左右。回溯的代价在最坏情况下就是指数，这题没有多项式解。

## 六、一句话记住

```
   '#' 是借调用方的格子当 visited，但每个 return 路径都写回 temp —— 连调两次棋盘完全一致（对照 p200/p994 的永久改写）；
   word 为 null/空串给 true，board 为 null 才 NPE；0 行 0 列都给 false（board[0].length 写在循环体里，0 行时不求值）；
   锯齿矩阵 AIOOBE（列数统一取 board[0].length）；大小写敏感，'a' 找 "A" 是 false；
   exist 里 board[i][j] == words[0] 的预筛：200×200 只有 1 个 A 时 0 ms；
   20,000 组与 boolean[][] visited 参考 0 差异（9,724 组答案为 true）；
   深度 = 词长：6,727 层能过、7,260 层爆，200×200/300×300 的迭代 DFS 只要 6/3 ms；
   题面 m,n ≤ 6、词长 ≤ 15，深度最多 15 层 —— 爆栈只在题面之外；
   全 A 棋盘 + 词尾不存在的字母：k=4..9 实测 37/100/255/625/1551/3896 µs，每加一字符约 ×2.5。
```
