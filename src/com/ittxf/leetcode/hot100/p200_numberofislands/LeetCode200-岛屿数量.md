# LeetCode 200 岛屿数量（淹没式 DFS，会抹掉调用方的地图）

> 对应程序：[LeetCode200_NumberOfIslands.java](./LeetCode200_NumberOfIslands.java)
> `main` 那张 4×5 的图，实测：
>
> ```
> 1
> ```

---

## 一、数岛屿 = 数"第一次踩到陆地"的次数

```java
for (int i = 0; i < grid.length; i++)
    for (int j = 0; j < grid[0].length; j++)
        if (grid[i][j] == '1') {
            count++;          // 只在发现新陆地时 +1
            dfs(grid, i, j);  // 立刻把整座岛淹掉
        }
```

`dfs` 的作用不是"找答案"，而是**把这座岛从地图上抹掉**，好让外层双重循环之后再也踩不到它：

```java
private void dfs(char[][] grid, int i, int j) {
    if (i < 0 || i >= grid.length || j < 0 || j >= grid[0].length || grid[i][j] != '1') return;
    grid[i][j] = '0';        // 先标记，再往四周走
    dfs(grid, i + 1, j);
    dfs(grid, i - 1, j);
    dfs(grid, i, j + 1);
    dfs(grid, i, j - 1);
}
```

`grid[i][j] = '0'` 必须在四次递归**之前**。放到后面写，相邻两个格子会互相把对方当新陆地反复递归，直接爆栈。这一行同时充当了 visited 数组，所以不需要额外空间。

四个方向是上下左右，**不含对角线**：`{{1,0},{0,1}}` 实测给 2（两块岛），符合题面的四连通定义。

## 二、最大的副作用：入参被改了

`dfs` 直接在传进来的 `grid` 上写 `'0'`。同一份地图连调两次：

```
第1次 -> 1
第2次 -> 0     ← '1' 全被改成 '0' 了，调用方的地图已经是一片海
```

不报错、第二次输出还很"合理"。要复用地图就得自己先拷贝一份。这份实现没有任何说明，注释里也只讲了"淹没算法"的思路，没提它淹的是别人家的地。

## 三、边界与异常

| 输入 | 结果 |
| --- | --- |
| 第二张示例图（LeetCode 例 2） | 3 |
| `null` | 0 |
| `new char[0][0]` | 0 |
| 3 行 0 列 | 0 |
| 全 `'0'` | 0 |
| **锯齿矩阵**（第 1 行 3 列、第 2 行 1 列） | `ArrayIndexOutOfBoundsException: Index 1 out of bounds for length 1` |

锯齿那条的根因是内层循环和 `dfs` 的边界判断都用了 `grid[0].length` 当统一列数。题面保证是矩形，所以不触发；但只要有人传进来一个每行长度不同的数组，就会在第二行越界。开头的 `grid.length == 0` 挡得住"没有行"，挡不住"行里没有列"和"列数不齐"。

## 四、随机对拍

20,000 张随机 1..8 × 1..8 网格，与并查集（union-find）参考实现对比：

```
岛屿数不一致 = 0
```

并查集把相邻的 `'1'` 合并到同一集合，最后数根节点的个数 —— 和"淹没"是完全不同的思路，能对上就说明四连通语义没写歪。

## 五、递归深度：这份的爆栈线特别低

`dfs` 的栈深度等于**最长的一条陆地路径**，不是格子总数的对数：

| 形状 | 规模 | 他的递归 DFS | BFS 参考 |
| --- | --- | --- | --- |
| 全 1 方阵 | 100 × 100 | 1，0 ms | 1 |
| 全 1 方阵 | 200 × 200 | `StackOverflowError` | 1 |
| 全 1 方阵 | 300 × 300 / 500 × 500 / 800 × 800 | `StackOverflowError` | 1 |
| 蛇形单条陆地 | 40,000 格 | `StackOverflowError` | — |

逐档试探全 1 方阵，**第一个爆栈的边长是 110**（默认栈）。110×110 = 12,100 个格子就撑不住了，因为 DFS 在全 1 网格上会走出一条覆盖几乎所有格子的长路径，深度接近格子总数。

这是本仓库里爆栈门槛最低的一份：`p104` 要 5 万节点的斜链、`p105` 要 1 万，而这里 1.2 万格就倒。题面 `m, n ≤ 300`（最多 9 万格）**正好落在会爆栈的区间里** —— LeetCode 的判题栈通常比本地默认大，所以线上能过，本地跑 300×300 全 1 会炸。改成显式栈的 BFS/DFS 就彻底免疫（实测 800×800 也是 1）。

## 六、一句话记住

```
   count++ 只在踩到新陆地时发生，dfs 负责把整座岛抹成 '0'；
   grid[i][j] = '0' 必须在四次递归之前，否则相邻格互相递归爆栈；
   四连通不含对角线：{{1,0},{0,1}} → 2；
   20,000 组与并查集 0 差异；
   入参被就地抹平：同一份地图连调两次给 1 然后 0；
   锯齿矩阵 AIOOBE（统一用 grid[0].length 当列数）；
   全 1 方阵边长 110 就爆栈（1.2 万格），300×300 也在题面范围内 —— 换显式栈才安全。
```
