# LeetCode 2 两数相加（低位在前的链表，天然适合从个位开始竖式）

> 对应程序：[LeetCode2_AddTwoNumbers.java](./LeetCode2_AddTwoNumbers.java)
> `main` 造了两个数：`2 -> 4 -> 3`（即 342）和 `5 -> 6 -> 4`（即 465），实测输出：
>
> ```
> 相加后的链表: 7 -> 0 -> 8
> ```
>
> 342 + 465 = 807，反过来存就是 `7 -> 0 -> 8`。

---

## 一、竖式怎么落到两条链表上

LeetCode 把数字**倒着存**（表头是个位），这反而省掉了"先反转再相加"的一步：两条链表同时从头走，就是竖式从右往左算。

```java
int val1 = (l1 != null) ? l1.val : 0;
int val2 = (l2 != null) ? l2.val : 0;
int sum = val1 + val2 + carry;
carry = sum / 10;
cur.next = new ListNode(sum % 10);
```

`main` 那组数据的逐位推演：

| 轮次 | l1 | l2 | 进位 in | sum | 当前位 | 进位 out |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 2 | 5 | 0 | 7 | 7 | 0 |
| 2 | 4 | 6 | 0 | 10 | 0 | 1 |
| 3 | 3 | 4 | 1 | 8 | 8 | 0 |
| 4 | null | null | 0 | — | 停止 | — |

两条链表走完不等于算完：第 4 轮虽然两个指针都是 null，但 `carry` 可能还是 1。

## 二、循环条件里的第三个条件

```java
while (l1 != null || l2 != null || carry != 0)
```

前两个条件负责"还有位没加"，第三个负责"最高位还有进位"。删掉第三个，`99 + 1` 这种就会丢最高位。实测：

| 输入（低位在前） | 输出 | 说明 |
| --- | --- | --- |
| `[5] + [5]` | `[0, 1]` | 个位进位，必须多长一位 |
| `[9,9,9,9] + [1]` | `[0, 0, 0, 0, 1]` | 连续进位 4 次 |
| `[9,9,9,9] + [9,9,9]` | `[8, 9, 9, 0, 1]` | 9999 + 999 = 10998 |
| `[0] + [1,2,3,4]` | `[1, 2, 3, 4]` | 短链表按 0 处理 |

`carry` 只可能是 0 或 1：最大 9 + 9 + 1 = 19，进 1。

## 三、长度不等怎么对齐

`(l1 != null) ? l1.val : 0` 把"短的那条先走完"变成"缺的位补 0"，所以不需要先求长度、也不需要补齐链表。`l1 = l1.next` 前有 `if (l1 != null)`，否则走到 null 之后再取 next 会 NPE。

## 四、这份实现新建了整条结果链

`dummy` 是虚拟头节点，结果全部 `new ListNode(...)`，**入参没有被改动**：

```
相加后原 list1 = [2, 4, 3], 原 list2 = [5, 6, 4]
```

这一点和同批的 21 / 23 / 24 / 25 / 148 不同 —— 那几份都是复用原节点、只改 `next`，调用方的链表会被"拆开"。

## 五、差分对拍与代价

固定种子 20,000 组，两条链表长度各 1..200，与 `BigInteger` 相加后反转对比：

```
与 BigInteger 不一致 = 0
```

长度 1 万位的两个数：**0.06 ms**，结果 10,001 位。因为只扫一遍，`O(max(m, n))` 时间；空间就是结果本身的 `O(max(m, n))`。

## 六、一句话记住

```
   低位在表头 = 竖式从个位开始：两根指针一起走，sum = a + b + carry，
   当前位存 sum % 10、carry 存 sum / 10；
   循环条件必须带上 carry != 0，否则最高位进位整个丢掉；
   短的链表用 0 补位，走完的指针不要再 next；
   dummy 省掉"结果头节点"的分支；20,000 组与 BigInteger 0 差异，1 万位 0.06 ms。
```
