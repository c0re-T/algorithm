# LeetCode 4 寻找两个正序数组的中位数（双指针虚拟归并）

> 对应程序：[LeetCode4_MedianOfTwoSortedArrays.java](./LeetCode4_MedianOfTwoSortedArrays.java)
> `main` 传的是 `{1,2}` 与 `{3,4}`，实测：
>
> ```
> 2.5
> ```

---

## 一、不合并，只"虚拟地"走到一半

```java
for (int i = 0; i <= mn / 2; i++) {
    left = right;                       // left 记住上一轮的 right
    if (aStart < m && (bStart >= n || nums1[aStart] <= nums2[bStart])) {
        right = nums1[aStart++];
    } else right = nums2[bStart++];
}
if ((mn & 1) == 0) return (left + right) / 2.0;
else return right;
```

像拉链一样每次从两个数组头里取较小的那个，只走到 `mn / 2` 就停：奇数长度时 `right` 就是中位数，偶数长度时 `left` 和 `right` 是中间两个。没有新数组，空间 O(1)。

下标细节：`left = right` 写在取数之前，所以循环结束时 `left` 是**倒数第二次**取到的数；`mn = 0` 时循环仍会跑一次，见边界一节。

## 二、随机对拍

200,000 组随机的有序小数组（长度 0..5、值域 −10..10，排除双空）与"合并后排序取中位"参考：

```
194,380 组有效数据：0 差异
```

另外 20,000 组长度 0..8 的随机数据也是 0 差异。

## 三、边界

| 输入 | 结果 |
| --- | --- |
| `{}` + `{}` | `ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0`（`mn=0`，循环跑一次，else 分支去读 `nums2[0]`） |
| `{}` + `{1,2}` | 1.5（正确） |
| `{1,2}` + `{}` / `{5}` + `{}` | 1.5 / 5.0（都正确） |
| `{1}` + `{1}` | 1.0 |
| `{2,2,2}` + `{2,2}` | 2.0 |
| `{-5,-1}` + `{-3,0,4}` | −1.0（与参考一致） |
| `null` | `NullPointerException`（`nums1.length`） |

入参只读，连调两次结果一致。

## 四、两处 int 溢出：求和那一步

`(left + right) / 2.0` 是**先做 int 加法再除**：

```
{2_000_000_000} + {2_000_000_000}
原版 -> -1.47483648E8     真值 2.0E9
```

LeetCode 约束是 ±10⁷，两个 10⁷ 相加只有 2×10⁷，实测 `{10_000_000} + {10_000_000}` 给 `1.0E7`，安全。想更稳可以写 `left / 2.0 + right / 2.0`。

## 五、代价：O(m+n)，注释里那份还多一次拷贝

题面要求 `O(log(m+n))`，这份是**合并走一半**的 `O(m+n)`。实测 5,000,000 + 5,000,000：

| 写法 | 结果 | 耗时 | 额外内存 |
| --- | --- | --- | --- |
| 虚拟归并（本程序） | 4,999,999.5 | 3 ms | ~0 |
| 注释里的 `IntStream.concat` + `Arrays.sort` | 4,999,999.5 | 66 ms | 40 MB |

注释版结果也对（20,000 组对拍 0 差异），但多一次 1000 万元素的拷贝和排序。两个版本在 2×10⁹ 上都同样溢出。

## 六、一句话记住

```
   两个指针虚拟归并，只走到 mn/2，left/right 保存中间两个；
   194,380 组随机小数组 0 差异，20,000 组中等规模也 0 差异；
   双空数组 AIOOBE，单空数组正常；
   (left + right) / 2.0 先做 int 加法：{2e9}+{2e9} 给 -1.47483648E8（真值 2e9），题面 ±1e7 安全；
   O(m+n)：5e6+5e6 只要 3 ms，注释版 concat+sort 66 ms / 40 MB；
   题面要的是 O(log(m+n))，这份不是。
```
