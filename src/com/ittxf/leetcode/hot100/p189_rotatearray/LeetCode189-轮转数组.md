# LeetCode 189 轮转数组（先 `k % n`，再三段反转）

> 对应程序：[LeetCode189_RotateArray.java](./LeetCode189_RotateArray.java)
> `main` 用 `[1..7]`、`k = 3`，实测输出 `[5, 6, 7, 1, 2, 3, 4]`。原地修改，`void` 方法。

---

## 一、三段反转的推导

目标：把末尾 `k` 个元素搬到前面。三次反转刚好做到：

```
   原数组          1 2 3 4 5 6 7      k=3
   ① 整体反转      7 6 5 4 3 2 1
   ② 反转前 k 个   5 6 7 4 3 2 1      ← 末尾的 5 6 7 被"翻正"后到了前面
   ③ 反转剩下 n-k  5 6 7 1 2 3 4      ✓
```

为什么成立：整体反转把"顺序"和"位置"同时颠倒；再对两段各自反转一次，就把每一段内部的顺序翻回来，
于是只剩"两段互换位置"这个效果。**每段只被扫两遍，`O(n)` 时间、`O(1)` 空间。**

## 二、`k % n` 那一行是必需的

```java
k = k % n;   // 长度 7 走 8 步等于走 1 步
```

实测 `[1,2,3]`、`k = 4`（`k > n`）→ `[3, 1, 2]`，也就是走 1 步 ✓。
如果去掉取模，`reverse(nums, 0, k-1)` 会变成 `reverse(0, 3)`，越过数组尾 → 越界。
注释里那句"核心大坑"是对的。

但这一行也带来两个边界：

| 输入 | 结果 |
| --- | --- |
| `k = 0` | 反转 3 次等于没动（①②③ 两次整体反转抵消）✓ |
| `k = n` | `k % n = 0`，同上 ✓ |
| **空数组 + 任何 k** | **`ArithmeticException: / by zero`**（`k % 0`） |
| **`k = -1`** | **`ArrayIndexOutOfBoundsException: Index -1`**（`-1 % 7 = -1`，`reverse(k, n-1)` 从 -1 开始） |

空数组和负 `k` 题面都不会给（`1 <= n`、`0 <= k <= 10⁵`），所以交上去没事；
但当工具方法用时，第一行应该补 `if (n == 0) return;` 和 `k = ((k % n) + n) % n;`（负数的正规化取模）。

## 四、和"逐格右移"的代价对比

最直观的写法是"循环 k 次、每次把整个数组右移一格"，那是 `O(n·k)`。实测（`k = n/3`）：

| n | 三段反转 | 逐格右移 | 结果 |
| --- | --- | --- | --- |
| 20,000 | 0 ms | 8 ms | 一致 |
| 40,000 | 1 ms | 37 ms | 一致 |
| 80,000 | 1 ms | 146 ms | 一致 |

逐格右移的时间随 `n·k` 涨（n 翻倍 → ×4），三段反转始终读不到毫秒。
LeetCode 这题 n ≤ 10⁵、k ≤ 10⁵，逐格右移最坏 10¹⁰ 次移动，必超时 —— 这题考的就是"能不能想到反转"。

## 五、和 48 题的关系：反转/转置是同一族操作

`p48` 旋转图像是"先转置、再逐行反转"，这一题是"整体反转 + 两段反转"。
两者都把"移动一大片元素"拆成了若干次**成对交换**，从而做到 `O(1)` 额外空间。
**"用两次/三次反转代替一次搬移"是个反复出现的套路**，值得当成工具记住。

## 六、一句话记住

```
   整体反转 → 反转前 k 个 → 反转剩下的：三段反转把"末尾搬到前面"，O(n) 时间 O(1) 空间；
   k % n 是必需的（k > n 时直接越界），但空数组会让它 / by zero、负 k 会让 reverse 从 -1 开始越界；
   20,000 组随机（k 故意大于 n）与参考实现 0 差异；
   n=80,000 时三段反转 1 ms vs 逐格右移 146 ms（O(n) vs O(n·k)）；
   和 p48 的"转置 + 反转行"是同一族"用成对交换代替搬移"的技巧。
```
