# LeetCode 56 合并区间（排序之后只需和"结果集最后一个"比）

> 对应程序：[LeetCode56_MergeIntervals.java](./LeetCode56_MergeIntervals.java)
> `main` 用 `{{1,4},{2,3}}`，实测输出 `[[1, 4]]`（被包含的 `[2,3]` 被并掉）。

---

## 一、排序 + 一条边界判定

```java
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);   // 按起点排序
List<int[]> list = new ArrayList<>();
list.add(intervals[0]);
for (int i = 1; i < intervals.length; i++) {
    int[] current = intervals[i];
    int[] last = list.get(list.size() - 1);
    if (current[0] <= last[1]) last[1] = Math.max(last[1], current[1]);   // 有交叠 → 延长终点
    else list.add(current);                                              // 否则另起一段
}
```

排序的作用是**把"和之前任意一段可能重叠"降级成"只和结果集最后一段比较"**：
按起点有序之后，当前区间的起点一定不小于之前所有区间的起点，所以只要它和最后一段不重叠，就不可能和更早的重叠。

两个容易写错的细节：

- 合并时终点要取 **`max(last[1], current[1])`**，不是直接 `current[1]`：`[[1,10],[2,3]]` 里 `[2,3]` 被完全包含，
  直接赋值会把区间缩短成 `[1,3]`。
- 判定的等号：`current[0] <= last[1]` —— `[[1,2],[2,3]]` 这种**端点相接**要合并；写成 `<` 就会留下两段。

## 二、差分对拍

固定种子 20,000 组随机（区间个数 0..5、起点 0..11、长度 0..5，包含大量包含/相接的情况）：

```
   与"另开一份副本、按起点排序后重新累积"的参考实现不同 —— 0 组
```

## 三、它会改调用方的数据（实测）

```java
merge(demo)   // demo = [[1,4],[0,2],[5,6]]
```

- `Arrays.sort(intervals, ...)` 把**传进来的数组本身**重排了（不是副本）；
- `last[1] = ...` 改的是原数组里的那**一个 int[]**（`list.add(intervals[0])` 放的是引用）；
- `intervals.length <= 1` 时 `return intervals` 直接把入参返回，连新数组都没建。

实测：

```
   调用前 [[1, 4], [0, 2], [5, 6]]
   调用后 [[0, 4], [1, 4], [5, 6]]
```

排序把 `[0,2]` 挪到了第一位；合并时 `last` 就是那个 `[0,2]` 对象本身（`list.add(intervals[0])` 放的是引用），
于是 `last[1] = max(2, 4) = 4` **直接改写进了调用方的那个 int[]** —— `[0,2]` 变成 `[0,4]`。
`[1,4]` 恰好 `max(4,4)=4` 没变，所以肉眼不容易看出"原数据被改了"。
只有 1 个区间时返回的是同一个数组对象：`true`。
LeetCode 只要求返回值，所以这不算错；但如果调用方之后还要用原区间，就得先自己拷贝。

**`null` 会直接 NPE**：现行版本第一行就是 `intervals.length`，没有 null 判断 ——
而他注释掉的那份旧代码里**有** `if (intervals == null || intervals.length == 0) return null;`。
注释掉一个版本时，顺带把它带的防御也注释掉了，这类"回退时丢守卫"很常见。

## 四、比较器 `a[0] - b[0]` 的溢出

减法比较器是经典隐患（Kruskal 那篇的 `compareTo` 也是这个）。纯算式实测：

```
   2000000000 - (-2000000000) 作为 int = -294967296   （真实差 4,000,000,000）
   Integer.compare(2000000000, -2000000000) = 1        （正确）
```

**这一题触发不到**：题面 `0 <= start <= end <= 10⁴`，差值最大 2×10⁴，离 `int` 边界很远。
但把它当通用工具方法、或者题目放宽到 ±10⁹ 时，`a[0] - b[0]` 就会把顺序排错 → 用
`Comparator.comparingInt(a -> a[0])` 或 `Integer.compare` 更稳。

## 五、`length <= 1` 那个提前返回

```java
if (intervals.length <= 1) return intervals;
```

- 长度 0：返回空数组 ✓（题面区间数 ≥ 1，所以走不到）；
- 长度 1：返回原数组 ✓（就是第三节说的"返回同一对象"）。

如果去掉这行，长度 0 会在 `list.add(intervals[0])` 处抛 `ArrayIndexOutOfBoundsException` —— 所以它是**必要的守卫**，
不是提前优化。

## 六、一句话记住

```
   按起点排序后，"和任意一段重叠"就降级成"只和结果集最后一段比"；
   终点取 max（[[1,10],[2,3]] 会被包含），判定用 <=（端点相接 [[1,2],[2,3]] 要合并）；
   20,000 组与参考实现 0 差异；它会就地排序并改写入参里的 int[]，长度 ≤1 时直接返回同一对象；
   null 会 NPE —— 注释掉的那份旧代码里反而有 null 判断（回退时丢了守卫）；
   比较器 a[0]-b[0] 这一题安全（约束 ±10⁴），但 ±10⁹ 时会把顺序排错。
```
