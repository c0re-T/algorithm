# LeetCode 141 环形链表（快慢指针一定会相遇，前提是无环时能及时刹车）

> 对应程序：[LeetCode141_LinkedListCycle.java](./LeetCode141_LinkedListCycle.java)
> `main` 造了三条链表，实测：
>
> ```
> 案例1 (有环) 结果: true       3 -> 2 -> 0 -> -4 -> (回到 2)
> 案例2 (无环) 结果: false      1 -> 2 -> null
> 案例3 (自身成环) 结果: true   1 -> (回到 1)
> ```

---

## 一、代码与"两步领先"的初值

```java
if (head == null || head.next == null) return false;
ListNode slow = head, fast = head.next;     // fast 一开始就领先一步
while (slow != fast) {
    if (fast == null || fast.next == null) return false;   // 无环：能走到头
    slow = slow.next;
    fast = fast.next.next;
}
return true;
```

`slow = head`、`fast = head.next` 是这份实现的一个小变体（更常见的是两个都从 head 出发再进循环）。
它带来的影响：

- **单节点自环**（`1 -> 1`）：`head.next` 不为 null，`fast` 直接等于 `head` → `slow == fast` 成立，
  while 一次都不进 → 返回 true ✓（案例 3 就是这个形状）。
- **单节点无环**：`head.next == null` → 第一行就返回 false ✓。
- **两节点环**（`1 -> 2 -> 1`）：slow=1、fast=2；循环里走一步后 slow=2、fast=2（`fast.next.next` 绕回来）→ 相遇 ✓。

如果两个指针都从 `head` 出发，上面这些形状也都能处理，只是第一次循环会空转一步 —— 两种写法都对，
**区别只在"单节点自环"这一步是走 while 还是在初值里就判定完**。

## 二、为什么"一定会相遇"

有环时，快指针每轮比慢指针多走一步，两者都在环里绕。设环长 `L`、进入环时两者相距 `d`，
每轮距离缩短 1，最多 `L` 轮必然追上 —— 所以不会"跨过去"（快指针一次跳两格也不会漏，因为差是 1 而不是 2）。

## 三、实测步数

用同一份逻辑统计"慢指针走了几步"（不含初值那一步）：

| n | 环入口 pos | 结果 | 慢指针步数 |
| --- | --- | --- | --- |
| 10 | −1（无环） | false | 4（走到 null 就停） |
| 10 | 0（头自环） | true | 9 |
| 10 | 5 | true | 9 |
| 2 | 0 | true | 1 |
| 2 | 1 | true | 1 |

步数上界是 `n`（无环时走完就停、有环时最多绕一圈就相遇）—— 这比"用 HashSet 记录访问过的节点"省掉了 `O(n)` 空间。

## 四、差分对拍

固定种子 20,000 组随机（长度 1..8，随机决定是否把尾节点指回某个位置），与"把节点塞进 `HashSet`、
重复出现就是有环"的参考实现比：

```
   不同 —— 0 组
```

## 五、代价

```
   n = 1,000,000 有环（尾接回中间）：快慢指针 4 ms
   用 HashSet：时间同量级，但要多存 100 万个节点引用（约 8 MB 起步，还有哈希桶开销）
```

`O(n)` 时间、`O(1)` 空间，是这题的标准答案。

## 七、一句话记住

```
   慢 1 步、快 2 步：有环必相遇（每轮距离缩短 1），无环靠 fast == null || fast.next == null 刹车；
   这份把 fast 初始化成 head.next，好处是单节点自环在 while 之前就判定完了；
   第一行挡 null 和单节点（无环）——少了它，`head.next` 会 NPE；
   20,000 组与 HashSet 参考 0 差异；步数 ≤ n；n=100 万实测 4 ms，O(1) 空间。
```
