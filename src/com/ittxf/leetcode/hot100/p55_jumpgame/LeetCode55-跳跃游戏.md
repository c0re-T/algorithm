# LeetCode 55 跳跃游戏（维护能到达的最远下标）

> 对应程序：[LeetCode55_JumpGame.java](./LeetCode55_JumpGame.java)
> `main` 跑两组示例，实测：
>
> ```
> true
> false
> ```

---

## 一、不关心怎么跳，只关心最远能到哪

```java
int maxReach = 0;
for (int i = 0; i < nums.length - 1 && i <= maxReach; i++) {
    maxReach = Math.max(maxReach, i + nums[i]);
}
return maxReach >= nums.length - 1;
```

`maxReach` 是"从起点出发能覆盖到的最远下标"。只要 `i <= maxReach`，说明第 i 格本身站得住，就可以拿它的跳跃力去刷新覆盖范围。`O(n)` 时间 `O(1)` 空间，比可达性 DP 少一个数组。

30,000 组随机（长度 0..30，跳跃力 0..1 或 0..5，其中 15,077 组可达）与可达性 DP 对拍：**0 处差异**。

## 二、`i <= maxReach` 是这道题的命门

去掉这个条件，循环会走到站不住的格子上，用它们的跳跃力凭空扩大覆盖范围：

| 变体 | 差异 | 反例 |
| --- | --- | --- |
| 去掉 `i <= maxReach` | **9,806 / 30,000** | `{0,2,3}` 返回 **true**，应为 false |
| 改成严格 `i < maxReach` | **13,169 / 30,000** | 长度为 18 的可达数组被判 false |
| 返回值改成 `maxReach > n-1` | **2,379 / 30,000** | `{0}` 返回 **false**，应为 true |

`{0,2,3}` 是最小反例：起点跳跃力 0，一步也走不了，但下标 1 的 `1+2=3` 会把 `maxReach` 推到 3，越过终点。

严格小于之所以错得更多，是因为 `i == maxReach` 恰好是"刚好跳到这一格"的合法情形，把它排除掉等于禁止落在覆盖边界上。

`>=` 写成 `>` 则错在"终点就是当前最远点"的情形，单元素 `{0}` 时 `0 > 0` 为假。

## 三、`i < nums.length - 1` 换成 `i < nums.length` 是等价的

实测 **0 / 30,000 差异**。理由：走到最后一格时，若它可达则 `maxReach >= n-1` 早已成立，若不可达则 `i <= maxReach` 先失败 —— 多扫这一格不会改变返回值。

**同一个上界在 [LeetCode 45](../p45_jumpgameII/LeetCode45-跳跃游戏II.md) 里却是必需的**（那边改成 `i < n` 会错 9,236 / 30,000），因为 45 在循环体里计数，多走一格就多算一步。这组对比值得记住：判断"能不能到"和"最少几步"用的是同一副骨架，但边界敏感度完全不同。

## 四、边界

| 输入 | 结果 |
| --- | --- |
| `{}` | `true`（`0 >= -1`，空数组真空成立） |
| `{0}` | `true` |
| `{1}` | `true` |
| `{0,1}` | `false` |
| `{1,0}` | `true` |
| `{2,0,0}` | `true` |
| `{1,1,0,1}` | `false` |
| `null` | `NullPointerException: Cannot read the array length` |

空数组返回 true 是 `maxReach >= nums.length - 1` 的直接后果（0 ≥ -1）。题面保证 `1 <= nums.length`，不必当真。

## 五、`i + nums[i]` 会溢出

题面限定 `0 <= nums[i] <= 10^5`、长度 ≤ 10^4，相加最大约 1.1×10^5，安全。放宽到 int 全域：

| 输入 | 程序返回 | 可达性 DP |
| --- | --- | --- |
| `{MAX_VALUE,0,0}` | `true` | true（`0+MAX` 不溢出） |
| `{1,MAX_VALUE,0,0}` | **false** | **true** |
| `{1,MAX_VALUE,0,0,0}` | **false** | **true** |

`1 + Integer.MAX_VALUE` 溢出成 -2,147,483,648，`Math.max` 把它丢掉，`maxReach` 停在 1，于是**明明一步就能跳到终点却判 false**。和 p45 一样，错得安静。

入参只读，同一数组连调两次结果一致。

## 六、实测代价：失败会提前退出，成功不会

n=10,000,000：

| 输入形态 | 耗时 | 说明 |
| --- | --- | --- |
| 全部为 1 | **5 ms** | 扫完全程 |
| 全部为 0 | **0 ms** | i=1 时 `1 <= 0` 失败，立刻退出 |
| 首元素 = n、其余为 0 | **5 ms** | 第一格就覆盖终点，但**仍然扫完全程** |

第三行是个可优化点：`maxReach >= n-1` 一旦成立就可以直接 `return true`，程序没做这个提前返回。n=1e5 时贪心与 DP 都是 0 ms，规模不够看不出差别。

## 七、一句话记住

```
   只维护 maxReach，i<=maxReach 才允许用第 i 格刷新覆盖范围，O(n) 时间 O(1) 空间；
   30,000 组随机与可达性 DP 0 差异（15,077 组可达）；
   去掉 i<=maxReach 错 9,806/30,000（{0,2,3} 变 true），改严格 < 错 13,169，返回值改 > 错 2,379（{0} 变 false）；
   上界 i<n-1 换成 i<n 等价（0 差异），但同一改动在 45 题错 9,236/30,000；
   {} 返回 true（0>=-1 真空成立），{0}/{1} true，null NPE，入参只读；
   {1,MAX,0,0} 因 1+MAX 溢出被判 false（真值 true），不抛异常；
   n=1e7 全 1 用 5 ms、全 0 用 0 ms（提前退出）、首格覆盖终点仍要 5 ms（成功没有提前返回）。
```
