# LeetCode 560 和为 K 的子数组（`put(0, 1)` 那一行，与"有负数就不能用滑窗"）

> 对应程序：[LeetCode560_SubarraySumEqualsK.java](./LeetCode560_SubarraySumEqualsK.java)
> `main` 用 `nums = [1,2,3]`、`k = 3`，实测打印 `2`（`[1,2]` 和 `[3]` 两段）。
> 前缀和 + 一张"前缀和 → 出现次数"的哈希表。

---

## 一、把"区间和"变成"两个前缀和之差"

记 `pre[i] = nums[0] + ... + nums[i-1]`，那么子数组 `nums[l..r]` 的和就是 `pre[r+1] - pre[l]`。
要求它等于 `k`，等价于：**在当前前缀和 `pre` 之前，有多少个历史前缀和等于 `pre - k`**。
所以走过的每一步只做一件事：查表、把 `pre - k` 的次数累加进 `count`，然后把 `pre` 记进表。

```java
preSumMap.put(0, 1);                       // ← 这一行是整个方法的地基
for (int num : nums) {
    preSum += num;
    if (preSumMap.containsKey(preSum - k)) count += preSumMap.get(preSum - k);
    preSumMap.put(preSum, preSumMap.getOrDefault(preSum, 0) + 1);
}
```

**先查后存**这个顺序和两数之和那道是同一件事：先把当前前缀和存进去，就可能查到"自己"，
把空区间（长度为 0 的子数组）算成一段答案。

## 二、`put(0, 1)` 到底在补什么

它是"空前缀"。没有它，**从下标 0 就开始**的那些合法子数组会被漏掉，因为
`preSum - k == 0` 这种情形（需要历史前缀和 0）在表里查不到。实测把那一行删掉：

```
   [1,2,3]  k=3   完整 2   →  去掉 1     （少了 [1,2]）
   [3,1,1]  k=3   完整 1   →  去掉 0     （少了 [3]，整组答案没了）
   [0,0,0]  k=0   完整 6   →  去掉 3     （6 段里少一半）
   [1,-1,1,1,1] k=2  完整 4 →  去掉 3
```

固定种子 20,000 组随机（长度 1..10、值域 -2..4、`k` 取 -3..5）跑一遍：

```
   去掉 put(0,1) 后与暴力不同：6,077 组（30.39%）
   仍恰好相同：13,923 组（69.61%）
```

**十次里有七次它悄悄混过去了** —— 所以这个坑不能靠"随手跑两组"发现，必须专门造一个"从下标 0 起就到 k"的例子
（`[3,1,1]/3` 是最短的：去掉后答案直接归 0，最能露馅）。

## 三、差分对拍

固定种子 20,000 组随机（长度 1..14、值域 -3..5、`k` 取 -2..6，故意大量含负数与 0）：

```
   他的前缀和 + 哈希 与两重循环暴力不同 —— 0 组
```

## 四、为什么这题**不能**用滑动窗口（分三种数据实测）

这题最容易顺手写的就是双指针窗口（"子数组 + 求个数"看着太像滑窗题）。我把这份误用写法
（`while (sum > k) 缩左边界` 然后 `if (sum == k) count++`）按数据形态分开测，结果比"有负数就不行"这句口诀更细：

| 数据形态 | 与暴力不同的组数 | 说明 |
| --- | --- | --- |
| **严格全正数**（每格 ≥ 1）且 `k ≥ 1` | **0 / 50,000** | 居然全对，见下面解释 |
| 允许 0（非负） | **10,306 / 50,000** | 一个右端点对应多个左端点了 |
| 全正数但 `k = 0` | **20,000 / 20,000** | 全错，把空区间数进去了 |
| 含负数（题面就是 `[-1000, 1000]`） | 11,229 / 20,000（第三节那批） | 单调性彻底没了 |

三个层次各不相同，值得分别记住：

**① 为什么严格全正数时它反而是对的？** 因为每个元素 ≥ 1 时，固定右端点 `r`，`sum(l..r)` 随 `l` 右移**严格变小**，
所以"等于 k 的左端点"最多只有一个 —— 滑窗"每个右端点至多数一段"的缺陷暴露不出来。
这一档它对，纯属题面性质巧合，不是滑窗变强了。

**② 一旦允许 0：** 固定右端点可以有多个左端点（`[0,2]` 和 `[2]` 都等于 2），滑窗只会数到一个。实测找到的第一个反例是：

```
   nums = [0, 0, 2, 4, 4, 5, 5, 5, 0, 1, 5, 2], k = 0
   暴力 4 段，滑窗误用 12 段        ← 这一例是 k=0，多出来的 12 段里有 ③ 说的那种空区间
```

`k >= 1` 且带 0 的那部分反例我没有单独挑出来列，表里那 10,306 / 50,000 是**含 0 的全部数据**（`k` 从 0 起取）的合计。

**③ `k = 0` 是另一个毛病**：`while (sum > k)` 会把窗口一路缩到 `left > right`，此时 `sum == 0` 成立，
于是**把空区间当成一段**计进答案 —— 所以全正数 + `k=0` 是 100% 全错，而不是偶发。

**④ 含负数时**连"缩窗口能让和变小"都不成立，`while (sum > k)` 会乱缩、错过解：

```
   nums = [1,-1,1,1,1], k = 2：暴力 4、滑窗误用 2、前缀和 4 ✓
```

题面 `nums[i] ∈ [-1000, 1000]`，直接落在 ④ 这一档，所以**只能用前缀和 + 哈希**。
而 `count += map.get(preSum - k)` 里那个 `+=`（不是 `count++`）正是"同一个右端点可能有多个左端点"的记账方式 ——
它把 ② 那个缺陷一次性补掉了。

注释里那份两重循环是正确的（第三节对拍的参考实现就是它），只是 `O(n²)`；LeetCode 这题 `n ≤ 2×10³`，
两重循环 `4×10⁶` 其实也能过 —— 这一题的真正难点不是复杂度，是**思路选型**。

## 五、几处细节与边界

```
   空数组 -> 0（循环不进）
   k = 0 -> 也能算对：[0,0,0] k=0 -> 6、[2,-2,2,-2] k=0 -> 4，都和暴力一致
   map 里存的是次数而不是下标 —— 因为要的是"多少段"，不是"哪一段"
   preSum 溢出：题面 |nums[i]| ≤ 1000、n ≤ 2×10⁴ ⇒ |preSum| ≤ 2×10⁷，int 够用；
                但把它当通用工具用时，这条要重新算（和 p1 里 target-nums[i] 只剩 7% 余量是同一类账）
```

`getOrDefault(preSum, 0) + 1` 这一句如果写成 `put(preSum, 1)`（覆盖而不是累加），实测：

```
   [0,0,0]      k=0  暴力 6 | 覆盖次数版 3
   [1,-1,1,1,1] k=2  暴力 4 | 覆盖次数版 2
   [2,-2,2,-2]  k=0  暴力 4 | 覆盖次数版 3
   20,000 组随机（值域 -2..4、k 取 -3..5）与暴力不同 4,235 组
```

**"次数"这个语义和 `put(0,1)` 同等重要**，两处都在"记不记历史"上；`[1,1,1] k=2` 这种每组只命中一次的数组
在覆盖版里还是对的（实测仍是 2），所以它同样不会随手暴露 —— 得专门拿带 0 或带来回抵消的数组去测。

## 六、代价

```
   n=200：前缀和+哈希 0 ms（260 段） | 两重循环 0 ms（260 段）
   n=400：0 ms（580 段）           | 0 ms（580 段）
   n=800：1 ms（1,220 段）          | 0 ms（1,220 段）
```

小数据上完全看不出差别（甚至因为哈希开销略微更慢）—— 这一题的 `O(n)` 优势要到 `n` 很大时才现形。
**所以别用"实测差不多"来否定它值得学**：这题的价值在"遇到有负数的子数组计数问题，先想到前缀和而不是滑窗"。

## 七、一句话记住

```
   区间和 = 两个前缀和之差，问题变成"历史上出现过多少次 preSum - k"，所以累加的是次数（count += …）；
   put(0,1) 是空前缀，去掉它 [3,1,1]/3 从 1 变 0、[1,2,3]/3 从 2 变 1，且并非每次输入都露出来；
   先查后存，否则会把空区间算进答案（和两数之和同一条纪律）；
   滑窗误用要分档看：严格全正数且 k>=1 时它 50,000 组全对（固定右端点最多一个左端点），
   允许 0 就错 10,306/50,000，k=0 时把空区间数进去 20,000/20,000 全错，含负数则单调性直接没了；
   题面 nums[i] ∈ [-1000,1000] 落在最后一档 ⇒ 只能前缀和 + 哈希，count += 次数 就是把"一个右端点多个左端点"补回来；
   20,000 组与两重循环暴力 0 差异；注释那份两重循环是正确的，这题的难点是思路选型不是复杂度。
```
