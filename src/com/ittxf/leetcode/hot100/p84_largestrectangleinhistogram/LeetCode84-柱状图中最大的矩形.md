# LeetCode 84 柱状图中最大的矩形（单调栈 + 末尾哨兵）

> 对应程序：[LeetCode84_LargestRectangleInHistogram.java](./LeetCode84_LargestRectangleInHistogram.java)
> `main` 传的是 `{2,1,5,6,2,3}` 和 `{2,4}`，实测：
>
> ```
> 10
> 4
> ```

---

## 一、栈里存下标，高度单调递增；右边一矮就结算

```java
for (int i = 0; i < n + 1; i++) {
    int currentHeight = (i == n) ? 0 : heights[i];
    while (!stack.isEmpty() && currentHeight < heights[stack.peek()]) {
        int h = heights[stack.pop()];
        int w = stack.isEmpty() ? i : i - stack.peek() - 1;
        max = Math.max(max, h * w);
    }
    stack.push(i);
}
```

栈里存的是**下标**，对应高度从栈底到栈顶单调递增。当前高度比栈顶矮，说明栈顶那根柱子的右边界就是 `i`，可以结算：高度 `h` 已定，宽度是 `i - 左边界 - 1`（栈空时左边界算 −1，宽度就是 `i`）。

`i == n` 时用一个高度 0 的**哨兵**把栈里剩下的柱子全部结算 —— 这是最容易漏的一步。

## 二、对拍与变体

20,000 组随机数组（长度 0..11、高度 0..9）与 `O(n²)` 暴力：

| 版本 | 差异 |
| --- | --- |
| 原版（末尾哨兵） | **0** |
| 去掉哨兵（只循环到 n−1） | **8,248 / 20,000** |
| `currentHeight <` 改成 `<=` | 0 |

无哨兵的最小反例 `{9,4,2,8,3}`：原版 10，无哨兵给 9 —— 栈里剩下没结算的柱子被丢掉。`<=` 只是让相同高度的柱子提前结算，答案不变。

## 三、边界

| 输入 | 结果 |
| --- | --- |
| `{}` | 0（`n=0`，第一轮就是哨兵，栈空） |
| `null` | `NullPointerException: Cannot read the array length because "<parameter1>" is null` |
| `{5}` / `{0}` | 5 / 0 |
| `{0,0,0}` | 0 |
| `{1,2,3,4,5}` | 9（整段高 1） |
| `{5,4,3,2,1}` | 9（整段高 1） |
| `{2,2,2,2}` | 8 |

入参只读，连调两次结果一致。

## 四、int 乘法的天花板

题面 `n ≤ 10⁵`、`heights[i] ≤ 10⁴`，最大面积正好 `10⁹`，int 装得下：

```
1e5 根全 10000 -> 1,000,000,000（12 ms）
```

超出题面就会静默溢出（`h * w` 是 int 乘法）：

| 输入 | int 结果 | long 真值 |
| --- | --- | --- |
| 1e5 根全 30000 | 2,147,460,000 | 3,000,000,000 |
| 1e5 根递减 100000..1 | 2,147,455,494 | 2,500,050,000 |

## 五、代价

单调栈每个下标进栈一次、出栈一次，`O(n)`。实测 1e5 根全 10000 只要 **12 ms**，严格递减 0 ms；同样数据用 `O(n²)` 暴力要跑几十秒。

## 六、一句话记住

```
   栈存下标、高度单调递增；当前矮于栈顶就弹栈结算，宽度 = i - 新栈顶 - 1；
   i == n 的高度 0 哨兵负责把剩下的全结算；
   20,000 组随机与暴力 0 差异；去掉哨兵错 8,248/20,000（{9,4,2,8,3} 给 9，真值 10）；
   <= 变体答案不变；空数组 0、null NPE；
   题面内最大 1e9 不会溢出（1e5 × 1e4，12 ms），1e5 × 30000 会静默溢出成 2,147,460,000；
   O(n)，每根柱子最多进出栈一次。
```
