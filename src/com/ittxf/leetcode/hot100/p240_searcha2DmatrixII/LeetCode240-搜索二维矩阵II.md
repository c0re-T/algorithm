# LeetCode 240 搜索二维矩阵 II（从左下角出发，一步排除一行或一列）

> 对应程序：[LeetCode240_SearchA2DMatrixII.java](./LeetCode240_SearchA2DMatrixII.java)
> `main` 用 5×5 的示例矩阵找 `5`，实测输出 `true`。
> 矩阵性质：**每行从左到右升序、每列从上到下升序**（行与行之间没有整体大小关系）。

---

## 一、为什么选左下角

从左下角 `(m-1, 0)` 出发。这个点同时是**最后一行的最小值**（行升序）和**第 0 列的最大值**（列升序）。
两条排除规则各自成立的推理是：

```
   matrix[i][j] > target
       第 i 行里 j 及其右边都 ≥ matrix[i][j] > target，而 j = 0 时左边没有元素
       ⇒ 整行 i 都不可能是答案 → i--（排除一整行）

   matrix[i][j] < target
       第 j 列里 i 及其上边都 ≤ matrix[i][j] < target（列升序，上面更小）
       ⇒ 整列 j 都不可能是答案 → j++（排除一整列）
```

**每一步必然排除一整行或一整列，所以最多 m+n 步。** 右上角对称（同理，方向反过来）：
左上角/右下角不行 —— 从左上角出发，往右和往下都变大，`> target` 时两个方向都不能排除。

一度我把这两条写反过（"比它大排除整列"）—— 注意区分：**排除的是"当前这个点所在的那一整行/列"**，
而不是"下一步要去的方向"。

## 二、实测步数

在 3×3 矩阵上把 target 从 −5 扫到 20，记录每次 `i--`/`j++` 的次数：

```
   最大步数 = 5 = m + n - 1
   目标不存在时（-5 / 20）也正常返回 false
```

`m+n-1` 就是"从一角走到对角"的步数上界，符合第一节的论证。

## 三、差分对拍

固定种子 20,000 组随机矩阵（行 1..5、列 1..5，按 `max(上, 左) + 随机小增量` 生成，保证行列双有序）：

```
   与逐格暴力不同 —— 0 组
```

## 四、边界与前提

```
   空矩阵 new int[][]{} -> ArrayIndexOutOfBoundsException（matrix[0].length）
   1×1                  -> 正常
   target 比最小值小/比最大值大 -> 走完 m+n 步返回 false（不越界）
```

**这份实现完全依赖"行有序 + 列有序"这两个前提**，而且不会检查。如果矩阵只满足行有序（每行内部升序、但行间乱），
它会在第一步就按错误的假设排除掉整行/整列 —— 和二分那道"不检查数组是否有序"是同一种"前提写在使用者身上"的设计。
两题的对照：二分靠"排一次序"，240 靠"输入天然有序"。

## 五、和 74 题的区别

LeetCode 74（搜索二维矩阵）的条件更强：**每行的第一个数大于上一行的最后一个数**（整体可视为一维有序），
那题可以直接二分。240 的条件弱得多（只有行内、列内有序），所以只能用"阶梯式"走，
`O(m+n)` 而不是 `O(log(mn))`。**条件强弱决定算法**，这两题放一起看比单看一道清楚。

## 六、代价

```
   时间 O(m + n)，空间 O(1)
   m = n = 10⁵ 时最多 2×10⁵ 步；暴力是 10¹⁰ 格，直接超时
```

## 七、一句话记住

```
   左下角是"该行最小 + 该列最大"的交点：比 target 大就 i--（排除整行），小就 j++（排除整列），
   每步必排除一整行或一整列 → O(m+n)；左上/右下不行，因为两个方向都指向更大的值；
   20,000 组与暴力 0 差异，3×3 上实测最大步数 5 = m+n-1；
   它不检查"行/列是否有序"，前提写在使用者身上（和二分那道同一类）。
```
