# LeetCode 3 无重复字符的最长子串（`Math.max` 挡住的是往回退的 left）

> 对应程序：[LeetCode3_LongestSubstringWithoutRepeatingCharacters.java](./LeetCode3_LongestSubstringWithoutRepeatingCharacters.java)
> 滑动窗口 + 一张 `Map<Character, Integer>`（存每个字符最后出现的下标）。
> `main` 里用的是 `"1R1T7"`，实测打印 `4`（暴力也是 4，即 `R1T7`）。

---

## 一、窗口怎么动

```java
if (map.containsKey(c)) left = Math.max(left, map.get(c) + 1);   // 只有往前走，不回退
map.put(c, right);
maxLen = Math.max(maxLen, right - left + 1);
```

`"1R1T7"` 逐轮：

| right | c | map 里有吗 | left | 窗口 | maxLen |
| --- | --- | --- | --- | --- | --- |
| 0 | `1` | 无 | 0 | `1` | 1 |
| 1 | `R` | 无 | 0 | `1R` | 2 |
| 2 | `1` | 有，下标 0 | `max(0, 1) = 1` | `R1` | 2 |
| 3 | `T` | 无 | 1 | `R1T` | 3 |
| 4 | `7` | 无 | 1 | `R1T7` | **4** |

## 二、`Math.max` 那一层不是保险，是必需的

把 `left = Math.max(left, map.get(c) + 1)` 改成 `left = map.get(c) + 1`（直接赋值），实测：

| 输入 | 带 max（他的写法） | 不带 max | 暴力 |
| --- | --- | --- | --- |
| `abba` | 2 ✓ | **3** ✗ | 2 |
| `abbacd` | 4 ✓ | **5** ✗ | 4 |
| `tmmzuxt` | 5 ✓ | **6** ✗ | 5 |
| `abban` | 3 ✓ | **4** ✗ | 3 |
| `abbba` | 2 ✓ | **4** ✗ | 2 |

固定种子 50,000 组随机串（字母表只有 a/b/c，长度 1..14，制造大量回退场景）：

```
   带 max 错 0 次  |  不带 max 错 27,081 次（54.16%）
```

机制用 `abba` 说最清楚：

```
   r=0 a -> map{a:0}               left=0
   r=1 b -> map{a:0,b:1}           left=0，窗口 "ab"
   r=2 b -> 命中 b@1，left 跳到 2；map{a:0,b:2}    窗口 "b"
   r=3 a -> 命中 a@0！
            不带 max：left = 0+1 = 1  ← left 从 2 退回了 1
            窗口变成 s[1..3] = "bba"，长度 3 被记进 maxLen，但 "bba" 里有重复的 b
```

**问题不是"跳得不够远"，而是"往回跳"**：`map` 里留着的是这个字符**上一次**出现的位置，
那次出现可能早就被窗口甩在身后了。`Math.max` 就是把"只许前进"这条不变量写死。
注释里那句"取 max 是为了防止 left 指针往后退（例如 "abba" 的情况）" ✓ 说的正是这件事，而且他举的例子和实测一致。

## 三、注释有一处和代码不一致

```java
// key: 字符, value: 该字符最后出现的索引 + 1 （也就是如果遇到重复，left 应该跳跃到的位置）
...
map.put(c, right);                              // 存的是 right 本身，没有 +1
...
left = Math.max(left, map.get(c) + 1);          // +1 写在这里
```

`+1` 是在**取值那一行**加的，不是存的时候加的。两种写法都对，但注释描述的是另一种。
这一处的实际风险是：以后有人照着注释改成 `map.put(c, right + 1)`，却忘了把取值那行的 `+1` 删掉，
`left` 就会多跳一格、窗口偏小。实测这个"双重 +1"版本在 200,000 组随机串（字母 a-d、长度 1..14）里
**与暴力不同 101,958 次（51%）**，最短的反例是：

```
   "aab"    暴力 2 | 正确写法 2 | 双重 +1 -> 1
   "aabbcc" 暴力 2 | 正确写法 2 | 双重 +1 -> 1
```

（有意思的是 `"abcabc"`、`"abba"` 这两种常见例子在"双重 +1"下答案仍然对 —— 又一次说明"随手挑两个例子测不出注释与代码的差异"。）

## 四、和 438 题对照：这里用 `Map` 而不是数组

`Map<Character, Integer>` 不限字符集 —— 他 `main` 里的 `"1R1T7"` 就有大写 `'R'`、`'T'`，照跑不误。
同一个思路换成 `int[128]` / `int[26]` 就得先约束字符范围（438 那题用 26 格数组，遇到大写直接越界，
见 [LeetCode438 笔记](../p438_findallanagramsinastring/LeetCode438-找到字符串中所有字母异位词.md)第五节）。
**"用 Map 还是用定长数组"这一处选择，就是通用性和常数之间的取舍**：数组省掉哈希开销但把输入范围焊死在代码里。

## 五、边界实测

```
   p3("")    -> 0
   p3(null)  -> 0        （方法第一行 if (s == null || s.length() == 0) return 0;）
```

这两行判断在这份题解里是真起作用的（`p42` 也写了 null 判断，但 `p11`、`p283` 没写，传 null 会 NPE —— 各份不一致）。

## 六、代价

暴力是"每个起点往后探、用 `Set` 判重"，最坏 `O(n²)`；滑动窗口 `left`/`right` 都只往一个方向走，
每个字符最多进出窗口一次 → `O(n)`。这一题的 `n` 最大 5×10⁴，两种都跑得动，所以拿它体会"窗口不回头"这个概念比体会加速更有价值：

```
   双指针的意义在于：left 从不后退，所以外层 right 走 n 步、内层 left 总共也只走 n 步。
   而第二节那个"不带 max"的版本恰恰是让 left 后退了 —— 一旦允许后退，这套复杂度论证就不成立了。
```

**也就是说，那层 `Math.max` 不只是保正确，它还是"为什么是 O(n)"的前提。**

## 七、一句话记住

```
   left 只许前进：Math.max(left, map.get(c) + 1) 里那个 max 是复杂度论证和正确性的共同前提，
   去掉它 50,000 组随机串错 27,081 次，最短反例 "abba" 给 3（正确答案 2）；
   注释把 "+1" 说成存在 value 里，代码实际是取的时候才 +1；
   用 Map 而不是定长数组，才让 "1R1T7" 里的大写字母照跑；
   null 和空串在第一行就挡掉了。
```
