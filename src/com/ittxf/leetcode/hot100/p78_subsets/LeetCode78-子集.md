# LeetCode 78 子集（回溯：每个节点都是答案）

> 对应程序：[LeetCode78_Subsets.java](./LeetCode78_Subsets.java)
> `main` 传的是 `{1,2,3}`，实测：
>
> ```
> [[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
> ```

---

## 一、`res.add` 写在进函数的第一行，所以每个节点都收

```java
public void backtrack(int[] nums, int start, List<Integer> track, List<List<Integer>> res) {
    res.add(new ArrayList<>(track));      // 进来先存，不等叶子
    for (int i = start; i < nums.length; i++) {
        track.add(nums[i]);
        backtrack(nums, i + 1, track, res);  // i + 1：只能选后面的
        track.remove(track.size() - 1);
    }
}
```

组合 / 排列 / 子集三兄弟的差别就在这几行：组合在"和等于目标"时收，排列在"长度满了"时收，**子集什么都不用等** —— 决策树上每一个节点本身就是一个合法的子集。所以 `{1,2,3}` 给 2³ = 8 条，长度分布是 1 + 3 + 3 + 1。

顺序也由此决定：先序遍历。`[]` 最先，`[1,2,3]` 在 `[1,3]` 之前 —— **不是按长度排序的字典序**。

## 二、`i + 1` 写成 `i` 就没有终止条件了

组合总和那道题必须有 `i`（允许重复选），这道题必须是 `i + 1`。写成 `i` 实测：

```
i+1 写成 i = StackOverflowError: null
```

因为这份代码**没有别的触底条件**（不像组合有 `sum == target`、排列有 `path.size() == n`）。`i` 不前进，`start` 永远停在当前下标，`track` 无限增长，一路钻到栈溢出。

## 三、`res.add` 的位置决定一切

| 写法 | `{1,2,3}` 上的结果 |
| --- | --- |
| 原版（进函数就存） | 8 条：`[[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]` |
| 只在叶子存（`start == n` 时） | 4 条：`[[1,2,3], [1,3], [2,3], [3]]` |
| `res.add(track)` 不拷贝 | 8 条，全是 `[]` |

第二行只剩"最后一个元素必选"的那些子集；第三行是引用的老问题（回溯结束时 `track` 已清空）。20,000 组随机数据上两种错法各错 **17,768 组**。

## 四、含重复值：按位置枚举就会给出重复子集

```
{1,1}   = [[], [1], [1, 1], [1]]
{1,1,2} = [[], [1], [1, 1], [1, 1, 2], [1, 2], [1], [1, 2], [2]]
{1,1,1} = 8 条，去重后只有 4 条
```

仍然按位置枚举（`i + 1`），两个 `1` 被当成两个不同的元素，所以 `[1]` 出现两次、`[1,1]` 也算一个。第 90 题（子集 II）要在循环里加"同层跳过相同值"才能去重。题面保证互不相同。

## 五、边界与随机对拍

| 输入 | 结果 |
| --- | --- |
| `{}` | `[[]]`（空集的唯一子集是空集） |
| `{1}` | `[[], [1]]` |
| `{1,2}` | `[[], [1], [1,2], [2]]` |
| `{1,2,3,4}` | 16 条 |
| `null` | `NullPointerException: Cannot read the array length because "<parameter1>" is null` |

20,000 组随机（互不相同、长度 0..8）与**位掩码枚举**参考对拍（`mask` 从 0 到 2ⁿ，逐位取元素）：

```
原版 vs 位掩码参考: 差异 = 0
互不相同的输入上出现重复子集 = 0
```

同一实例连调三次给 `8 → 4 → 8`，`res` / `track` 都是局部变量。

## 六、规模：2ⁿ

| n | 条数 | 耗时 |
| --- | --- | --- |
| 10 | 1,024 | 0 ms |
| 15 | 32,768 | 1 ms |
| 18 | 262,144 | 8 ms |
| 20 | 1,048,576 | 37 ms |
| 22 | 4,194,304 | 193 ms |
| 23 | 8,388,608 | 488 ms |

递归深度只有 n 层。题面 `n ≤ 10`（最多 1,024 条）—— 这份代码跑到 n=23 也只是半秒，瓶颈同样是结果集大小而不是栈。
