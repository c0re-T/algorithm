## 一、四步动作

对每个有左子树的节点：

```java
TreeNode next = curr.left;
while (next.right != null) next = next.right;   // 1. 左子树的最右节点 = 前序里的前驱
next.right = curr.right;                        // 2. 原来的右子树挂到前驱后面
curr.right = curr.left;                         // 3. 左子树整体挪到右边
curr.left = null;                               // 4. 左指针清空
curr = curr.right;                              // 5. 走到下一个节点
```

为什么挂到"左子树的最右节点"上？因为展开后的顺序必须是**前序**：`根 → 左子树全部 → 右子树全部`。左子树展开成链之后，它的最后一个节点就是左子树里最右下的那个（前序意义下的末尾），原右子树只能接在它后面。

第 2、3 步的顺序不能换：先把 `curr.right` 存进 `next.right`，再把 `curr.left` 覆盖到 `curr.right`。反过来写第 3 步先执行，`curr.right` 就已经被左子树顶掉，原右子树整棵丢失。

第 4 步 `curr.left = null` 是题目要求（展开后所有左指针必须为 null）。实测删掉它：20,000 组里右链的值序列仍然全对，但**左指针残留**，检查"有没有节点还带左孩子"时全部不合格。

## 二、随机对拍

20,000 棵随机树（1..40 个节点），展开后沿 `right` 走出来的值序列，与原树的前序遍历对比：

```
值序列不一致        = 0
展开后仍有左孩子    = 0
```

`null` 传进去不抛异常（`curr = root` 就是 null，while 一次都不进）。对同一条已经展开的链再调一次，结果不变（幂等）—— 因为所有左指针都是 null，if 分支一次都不进。

## 三、内层 while 到底走多少步

看起来"每个节点都要找一次前驱"像是 O(n²)，实测不是：

| 形状 | n | 内层 while 总步数 | 外层步数 |
| --- | --- | --- | --- |
| 随机树 | 1,000 | 1,799 | 1,000 |
| 随机树 | 10,000 | 17,999 | 10,000 |
| 纯右斜链 | 任意 n | 0 | n |

随机树上内层步数约是外层的 1.8 倍，两个规模都是这个比例，**在测过的形状上是线性的**。原因是每条边最多被"当作右链走一次"：`next.right = curr.right` 把原右子树接下去之后，那段链随后会被外层逐个处理，不会重复从头找前驱。纯右斜链上 if 分支一次都不进，内层 0 步。

随机 n 从 2,000 到 10,000 实测都是 0 ms。这份是迭代 + 原地改指针，**没有递归，所以不存在斜链爆栈问题**；额外空间 O(1)。

## 四、注释里那份前序数组版

代码里注释掉的另一份写法是：先前序遍历把节点存进 `List`，再两两重连。它是对的，但要 `O(n)` 额外空间存列表，而且递归前序在深链上会爆栈。当前这份用"找前驱"换掉了那个列表，这正是题目进阶要求的 O(1) 空间。

文件顶上 `import java.util.ArrayList; import java.util.List;` 是给注释那份留的，当前实现一个都没用到。
