# LeetCode 763 划分字母区间（先记末次出现位置，再扫一遍收边界）

> 对应程序：[LeetCode763_PartitionLabels.java](./LeetCode763_PartitionLabels.java)
> `main` 跑两组示例，实测：
>
> ```
> [9, 7, 8]
> [10]
> ```

---

## 一、两遍扫描：第一遍记每个字母最后一次出现在哪

```java
int[] last = new int[26];
for (int i = 0; i < charArray.length; i++) {
    last[charArray[i] - 'a'] = i;
}

int left = 0, right = 0;
for (int i = 0; i < charArray.length; i++) {
    right = Math.max(right, last[charArray[i] - 'a']);
    if (i == right) {
        result.add(right + 1 - left);
        left = right + 1;
    }
}
```

一个片段合法的条件是：**片段里出现过的字母，不能在片段外再出现**。所以片段的右端至少要延伸到"片段内所有字母的末次位置"的最大值。第二遍扫描时 `right` 就是这个滚动最大值，一旦 `i == right`，说明当前片段已经把所有相关字母都圈进来了，可以在这里切。

`O(n)` 时间，额外空间只有一个 26 长的数组，`O(1)`。

对拍用了一条**思路完全不同**的参考：对每个候选切点，把左半段字母收成集合，逐个检查右半段有没有字母落在集合里，没有才允许切。20,000 组随机（长度 0..40、字母表 1..6 个字母）：**0 处差异**，且每组结果之和都等于串长（**0 处不符**）。再**穷举** `{a,b,c}` 上长度 1..5 的全部 **363 个串**：**0 处差异**。

## 二、`right + 1 - left` 里那个 `+1` 不能丢

`right` 和 `left` 都是下标，长度是 `right - left + 1`：

| 输入 | 原版 | 写成 `right - left` |
| --- | --- | --- |
| `"a"` | `[1]` | **`[0]`** |
| `"ab"` | `[1, 1]` | **`[0, 0]`** |
| `"abab"` | `[4]` | **`[3]`** |

20,000 组随机错 **19,524 处**，穷举的 363 个串**全部错**（长度至少为 1，每段都少 1）。

## 三、`left = right + 1` 也不能丢

漏掉它，`left` 永远停在 0，后面每段都从串首开始量：

| 输入 | 原版 | 漏掉 `left` 更新 |
| --- | --- | --- |
| `"bdccc"` | `[1, 1, 3]` | **`[1, 2, 5]`** |

20,000 组随机错 **2,286 处**。注意这个变体的结果之和会超过串长，"和等于 n"这条不变量刚好能抓住它。

## 四、必须是**末次**出现，且必须取 `Math.max`

| 变体 | 20,000 组随机 | 363 个穷举串 | `"abab"` |
| --- | --- | --- | --- |
| 原版（末次 + `Math.max`） | 0 | 0 | `[4]` |
| 记**首次**出现位置 | **18,519** | **348** | **`[1, 1]`** |
| `right = last[c]`，不取 `Math.max` | **14,624** | **228** | **`[3, 1]`** |

首次出现位置完全违背了"圈住所有同名字母"的要求，`"abab"` 会被切成两段，而两个 `a`、两个 `b` 都跨段了。

不取 `Math.max` 则会让 `right` **往回缩**：走到第二个 `a`（下标 2）时 `last['a']=2`，但 `right` 之前已经被 `b` 推到 3，直接赋值就退回 2，于是在下标 2 处误切。`right` 必须单调不减。

## 五、`i == right` 写成 `i >= right` 是等价的

实测 **0 / 20,000 差异**。因为 `right` 是 `last[...]` 的滚动最大值，而 `last[c] >= i` 对当前字母恒成立，所以 `right >= i` 永远成立，`>=` 退化成 `==`。

`charArray[i]` 换成 `s.charAt(i)` 也是 **0 / 20,000 差异**，n=1e7 时耗时 13 ms vs 14 ms，**这个规模量不出差别**。

## 六、边界：只吃小写字母

| 输入 | 结果 |
| --- | --- |
| `""` | `[]`（size=0） |
| `"a"` | `[1]` |
| `"abc"` | `[1, 1, 1]` |
| `"aaa"` | `[3]` |
| `"abab"` | `[4]` |
| 26 个字母各一次 | 26 个 `1` |
| `null` | `NullPointerException: Cannot invoke "String.toCharArray()"` |

`last` 只有 26 格，非小写字母直接越界（实测异常消息）：

| 字符 | `c - 'a'` | 异常 |
| --- | --- | --- |
| `'A'` | -32 | `Index -32 out of bounds for length 26` |
| `'1'` | -48 | `Index -48 out of bounds for length 26` |
| `' '` | -65 | `Index -65 out of bounds for length 26` |
| `'-'` | -52 | `Index -52 out of bounds for length 26` |
| `'中'` | 19916 | `Index 19916 out of bounds for length 26` |

题面保证只含小写字母，所以这里**不需要**换成 `HashMap`；但要知道它是"靠题面兜住"而不是"自身健壮"。

段数上限是 26（每段至少独占一个字母）：5,000 组 26 字母随机串，**0 组超过 26 段**。

入参只读，同一串连调两次结果一致。

## 七、实测代价

n=10,000,000：

| 输入形态 | 耗时 | 段数 |
| --- | --- | --- |
| 26 字母随机 | **13 ms** | 1 |
| 全部 `'a'` | **12 ms** | 1（长度 10,000,000） |
| `'ab'` 交替 | **18 ms** | 1 |

三种形态都只有一段 —— 随机串里 26 个字母的末次位置几乎都落在末尾附近，`right` 一路被推到串尾。**段数多的输入反而是"每个字母只出现一次"这种短串**，长随机串很难构造出多段。

## 八、一句话记住

```
   第一遍记每个字母的末次下标，第二遍滚动 right=max(right,last[c])，i==right 就切；
   20,000 组随机与"逐切点检查字母跨界"的暴力 0 差异，穷举 363 个串也 0 差异，段长之和恒等于 n；
   长度写成 right-left 错 19,524/20,000（"a" 从 [1] 变 [0]），穷举 363 个全错；
   漏掉 left=right+1 错 2,286（"bdccc" 从 [1,1,3] 变 [1,2,5]，和会超过 n）；
   记首次出现错 18,519、right 不取 Math.max 错 14,624（"abab" 分别变 [1,1] 和 [3,1]）；
   i>=right 与 charAt 版本都等价（0 差异），n=1e7 耗时 13 vs 14 ms 量不出差别；
   只吃小写字母：'A'→Index -32、'中'→Index 19916 越界，null NPE，段数上限 26；
   n=1e7 随机/全 a/ab 交替都只有 1 段，12–18 ms。
```
