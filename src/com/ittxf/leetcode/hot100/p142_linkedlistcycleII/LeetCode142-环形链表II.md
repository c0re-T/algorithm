# LeetCode 142 环形链表 II（相遇后，一个回表头、一个留原地，再同速走）

> 对应程序：[LeetCode142_LinkedListCycleII.java](./LeetCode142_LinkedListCycleII.java)
> `main` 造了三条链，实测：
>
> ```
> 案例1 (有环) 结果: 2
> 案例2 (有环) 结果: 1
> 案例3 (自身成环) 结果: null
> ```
>
> 注意 `main` 的注释和实际构造对不上：案例 2 注释写"无环链表"却传了 `pos = 0`（整条链成环）；

## 一、两阶段

```java
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) {
        ListNode ptr = head;
        while (ptr != slow) { ptr = ptr.next; slow = slow.next; }
        return ptr;
    }
}
return null;
```

第一阶段判环（141 题），相遇后进入第二阶段：`ptr` 回到表头，`slow` 留在相遇点，两者**都每次走一步**，再次相遇的位置就是环入口。

## 二、为什么"再走 a 步一定在入口相遇"

设：

- `a` = 表头到入口的距离；
- `b` = 入口到相遇点的距离；
- `c` = 相遇点回到入口的距离（`b + c` = 环长）。

相遇时慢指针走了 `a + b`，快指针走了 `a + b + (b + c)`（至少多绕一圈）。快是慢的两倍：

```
2(a + b) = a + 2b + c   =>   a = c
```

也就是说：**表头到入口的距离 = 相遇点到入口的距离**。`ptr` 从表头走 `a` 步到入口，`slow` 从相遇点走 `c = a` 步也到入口，两人同速，正好在入口碰头。

## 三、实测步数

对 11 种 (节点数, 入口下标) 组合统计（`ptr` 步数 = 第二阶段走的步数）：

| n | 入口下标 | 返回入口 | ptr 步数 | slow 总步数 |
| --- | --- | --- | --- | --- |
| 1 | 0 | ✓（值 1） | 0 | 1 |
| 2 | 0 | ✓（值 1） | 0 | 2 |
| 2 | 1 | ✓（值 2） | 1 | 2 |
| 3 | 2 | ✓（值 3） | 2 | 4 |
| 4 | 1 | ✓（值 2） | 1 | 4 |
| 5 | 0 | ✓（值 1） | 0 | 5 |
| 5 | 3 | ✓（值 4） | 3 | 7 |
| 10 | 4 | ✓（值 5） | 4 | 10 |
| 10 | 9 | ✓（值 10） | 9 | 18 |
| 100 | 0 | ✓（值 1） | 0 | 100 |
| 100 | 99 | ✓（值 100） | 99 | 198 |

`ptr` 步数恰好等于入口下标（= a），与上面的推导一致。无环时第一阶段就走了：

| n | 返回 | 循环轮数 |
| --- | --- | --- |
| 1 | null | 0 |
| 2 | null | 1 |
| 3 | null | 1 |
| 10 | null | 5 |
| 100 | null | 50 |

## 四、差分对拍与代价

长度 1..30、随机是否成环、随机入口，固定种子 20,000 组，与"HashSet 记录第一个重复节点"的参考实现对比：

```
返回节点不一致 = 0
```

100 万节点、入口在正中间（下标 500,000）：**2.9 ms**。两阶段合计仍是线性步数，`O(n)` 时间、`O(1)` 空间。

## 五、一句话记住

```
   第一阶段慢 1 快 2 找相遇；相遇后 ptr 回表头，ptr 与 slow 同速走，碰头处就是入口；
   推导只有一行：2(a+b) = a+2b+c => a = c；
   实测 11 种形状 ptr 步数 = 入口下标，20,000 组与 HashSet 0 差异；
   100 万节点 2.9 ms，O(1) 空间；
   main 的案例 2/3 注释与 pos 参数对不上（标签错，代码对）。
```
