# LeetCode 48 旋转图像（转置 + 逐行反转，`j = i` 那一格是关键）

> 对应程序：[LeetCode48_RotateImage.java](./LeetCode48_RotateImage.java)
> `main` 用 `{{1,2,3},{4,5,6},{7,8,9}}`，实测输出 `[[7, 4, 1], [8, 5, 2], [9, 6, 3]]`（顺时针 90°）。原地修改。

---

## 一、两步

```java
// ① 转置：沿主对角线翻转
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++) { swap(matrix[i][j], matrix[j][i]); }
// ② 每一行左右反转
for (int[] row : matrix) for (int j = 0; j < row.length / 2; j++) swap(row[j], row[row.length-1-j]);
```

用 `{{1,2,3},{4,5,6},{7,8,9}}` 走一遍：

```
   原矩阵        1 2 3        转置后        1 4 7        行反转后      7 4 1
                 4 5 6         ←            2 5 8      →                8 5 2
                 7 8 9                      3 6 9                      9 6 3
```

**`j` 从 `i` 开始而不是从 0**：从 0 开始会把每一对再交换一次，等于什么都没做（转置两遍 = 原矩阵）。
这是这段代码唯一容易写错的地方，而且"转两遍"的结果看起来"很规整"，不容易发现 —— 只有拿非对称矩阵才能测出来
（`{{1,2},{3,4}}` 转两遍还是 `{{1,2},{3,4}}`，而正确答案是 `{{3,1},{4,2}}`）。

## 二、为什么是"转置 + 行反转"

顺时针 90° 的坐标映射是 `(i, j) → (j, n-1-i)`。拆成两步：

```
   转置        (i, j) → (j, i)        换行换列
   行反转      (i, j) → (i, n-1-j)    每行左右翻
   合起来      (i, j) → (j, i) → (j, n-1-i)   ✓
```

逆时针 90° 则是"转置 + 列反转"（或"左右反转 + 转置"），顺序不能乱换。

## 四、边界

```
   n = 1    -> 原样
   n = 2    -> {{3,1},{4,2}}
   非方阵（2×3）-> ArrayIndexOutOfBoundsException
```

非方阵会崩，是因为转置那一步访问 `matrix[j][i]`，而 `j` 最大到 `n-1`、`i` 最大到 `n-1`，
只对方阵成立。**题面明确保证是 n×n**，所以这是"靠题面约束兜住"的又一处
（和 238 的 int 溢出、56 的比较器、189 的 k 边界同类）。

## 五、和 189 的关系

`p189` 轮转数组是"整体反转 + 两段反转"，这一题是"转置 + 行反转" —— 都是**用成对交换代替搬移**，
都能做到 `O(1)` 额外空间：

| | 189 轮转 | 48 旋转 |
| --- | --- | --- |
| 目标 | 一维循环移位 | 二维旋转 |
| 分解 | 3 次反转 | 1 次转置 + n 次行反转 |
| 交换次数 | 约 n | 约 n²/2 + n²/2 = n²（每格都动） |

时间都是 `O(元素个数)`。这类题值得记的不是代码，而是**"能不能把置换分解成若干次反转"**这个思路。

## 六、一句话记住

```
   顺时针 90° = 转置 + 逐行反转（坐标映射 (i,j) -> (j, n-1-i)）；
   转置的内层 j 必须从 i 开始，从 0 开始会转两遍等于没动 —— 只有非对称矩阵能测出来；
   20,000 组随机方阵与参考实现 0 差异；非方阵会 AIOOBE（题面保证 n×n）；
   和 189 一样属于"用成对交换实现 O(1) 空间置换"的技巧族。
```
