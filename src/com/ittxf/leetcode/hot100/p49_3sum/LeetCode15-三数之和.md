# LeetCode 15 三数之和（排序之后才有"跳过重复"可写）

> 对应程序：[LeetCode49_3Sum.java](./LeetCode49_3Sum.java)（包名 `p49_3sum`，见第八节）
> `main` 用 `[-1,0,1,2,-1,-4]`，实测输出两行：
>
> ```
> [-4, -1, -1, 0, 1, 2]
> [[-1, -1, 2], [-1, 0, 1]]
> ```
>
> 第一行是方法里那句 `System.out.println(Arrays.toString(nums))` 打出来的 —— 它顺手把入参排序了。

## 一、三层结构

```java
Arrays.sort(nums);                                    // 双指针和去重都靠它
for (int i = 0; i < nums.length - 2; i++) {
    if (nums[i] > 0) break;                           // 剪枝
    if (i > 0 && nums[i] == nums[i-1]) continue;      // 第一个数去重
    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) { result.add(...);
            while (left < right && nums[left] == nums[left+1]) left++;    // 第二个数去重
            while (left < right && nums[right] == nums[right-1]) right--; // 第三个数去重
            left++; right--;
        } else if (sum < 0) left++; else right--;
    }
}
```

**排序是这一切的前提**：只有排过序，`sum < 0 → left++` 才是"把和变大"的唯一方向，
也只有排过序，"重复的值挨在一起"才让 `continue` 能跳过重复。
这也正是二分查找那篇笔记里"不检查有序就大量漏答"的正面版本 —— 这里不但依赖有序，还主动把它造出来。

`nums[i] > 0` 就 `break` 是对的：`i` 之后的数都 ≥ `nums[i]`（已排序），三个正数加不出 0。
注意它只在 target = 0 时成立；如果题目换成"和为 target"，这条剪枝要看 `3 * nums[i] > target` 才行。

## 二、和"暴力 + 按值去重"对拍

固定种子 20,000 组随机（长度 3..12、值域 -4..4，故意制造大量重复值），把方法返回的三元组集合与
"三重循环枚举 + 按值收进 Set"的结果比：**不同 0 组**。

他 `main` 那组也一致：

```
   方法返回   [[-1, -1, 2], [-1, 0, 1]]
   参考去重后 [[-1, -1, 2], [-1, 0, 1]]
```

## 三、那三处跳重各自在挡什么（实测，含两个反直觉结果）

他自己在那段前写了"错误的会重复"。实测这段代码在他的用例上给出 **3 组**：

```
   [[-1, 0, 1], [-1, 2, -1], [0, 1, -1]]        ← 同一个值组合被记了三次
```

因为数组里有两个 `-1`，而 `i/j/k` 是**按下标**枚举的：`(-1)₂+0+1` 和 `(-1)₅+0+1` 是两个不同的下标三元组、相同的值。
20,000 组随机数据里，**有 12,249 组（61.25%）的组数对不上**去重后的结果 —— 重复是常态，不是巧合。

主方法里那三处跳重是配套的，我把它们逐个去掉跑了一遍，结果和直觉不一样：

**① 去掉 `if (i > 0 && nums[i] == nums[i-1]) continue;`（第一个数不去重）** —— 这条最关键，实测：

```
   [-1,0,1,2,-1,-4] -> [[-1,-1,2], [-1,0,1], [-1,0,1]]   3 条（两个 -1 各跑一遍内层）
   20,000 组随机     -> 8,176 组（40.88%）条数变多
```

**② 去掉内层那两个 `while` 跳重**

```
   [-1,0,1,2,-1,-4] -> 仍然 2 条，且与完整写法完全相同   ← 他的用例测不出来！
   [-2,0,0,2,2]     -> [[-2,0,2], [-2,0,2]]  2 条（完整写法只有 1 条）
   20,000 组随机     -> 3,768 组（18.84%）条数变多；值集合本身 0 组不同
```

**只多、不漏**：那 3,768 组全是"同一个值组合被记两次"，所以它不会给出错误答案，只会给出重复答案 ——
这也是为什么 ①② 的差别在他的示例上看不出来（示例里重复的 `-1` 恰好被 ① 挡住了）。

**③ 去掉命中后收尾的 `left++; right--;`** —— 这条最意外：

```
   [-1,0,1,2,-1,-4] -> 死循环，靠我加的"攒够 5001 条就退出"的保护才跳出来（去重后只剩 1 组）
```

因为命中之后如果两个指针都不动（且当前值不重复，那两个 `while` 也不会挪），下一轮 `sum` 还是 0，
就永远停在这一组上。**收尾那两句不是"顺手推进一下"，而是终止条件的一部分。**

所以三处的分工是：① 和 ② 管"不重复输出"，③ 管"能停下来"；②单独去掉时只在有连续重复值的数据上才现形，
③单独去掉时直接在最常见的无重复数据上死循环。

## 四、`result` 里装的是值不是下标

`Arrays.asList(nums[i], nums[left], nums[right])` 放进结果的是**排完序之后的值**。
所以这题的答案本来就只能按值给出（题面也要求"答案中不应包含重复的三元组"，是按值判重）。
但如果哪天要返回下标，这套去重逻辑立刻失效 —— 排序已经打乱了下标，得额外带一个 `(值, 原下标)` 的结构。

## 五、方法里的两个副作用

```java
Arrays.sort(nums);                                  // 改的是调用方传进来的那个数组
System.out.println(Arrays.toString(nums));          // 每次调用都多打一行
```

- 传进去的 `nums` 被就地排序了。和 Floyd 那份 `this.distance = matrix` 是同一类事：**方法接管了调用方的数据**。
  LeetCode 上不碍事，但在真实项目里，如果调用方之后还要用原始顺序（比如按下标答题、或者要打印原数组），就被改坏了。
  防御写法是 `int[] a = nums.clone(); Arrays.sort(a);`。
- 那行 `println` 是本地观察排序结果用的，交上去会多输出一行。这类"调试打印忘删"在 `p128` 里也有一处（打印 `numSet`）。

## 六、边界实测

| 输入 | 返回 | 说明 |
| --- | --- | --- |
| `null` | `[]` | 方法第一行 `nums == null \|\| nums.length < 3` 挡了 |
| `[1,2]` | `[]` | 长度不足直接返回，不会走 `nums.length - 2` 的负数下标 |
| `[0,0,0]` | `[[0, 0, 0]]` | 全重复也只出一组 |
| `[1,1,1]` | `[]` | 没有 0 也没有负数 |

`i < nums.length - 2` 这个上界配着 `nums.length < 3` 的提前返回是安全的：长度 3 时只跑 `i = 0`。

## 七、代价

`n = 300`、值域 -30..30 的随机数组（实测两组实现答案一致，都是 481 组）：

```
   排序 + 双指针     0 ms
   三重循环 + Set 去重  22 ms
```

差在 `O(n²)` vs `O(n³)`。LeetCode 这题 n ≤ 3000，三重循环是 2.7×10¹⁰ 次，直接超时 —— 那份注释掉的写法在本地小数据上"看起来对"，规模一上去就是另一回事（和马踏棋盘里"排序关掉"是同一个教训：常数和指数都得靠实测看）。

## 八、题号和包名：`p49_3sum`

三数之和在 LeetCode 上是 **第 15 题**（`15. 三数之和`），`49` 是字母异位词分组 —— 也就是同层那个 `p49_groupanagrams`。
所以现在 `hot100/` 下有两个 `p49_*` 目录、两个类分别叫 `LeetCode49_3Sum` 和 `LeetCode49_GroupAnagrams`，
题号写串了。因为包名不同（`p49_3sum` 与 `p49_groupanagrams`），编译和运行都不受影响（实测 23 个文件一次编译通过），
纯粹是检索和以后加题时的混淆源 —— 比如再写一道真的 49 题变体时就没法编号了。
