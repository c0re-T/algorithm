# LeetCode 206 反转链表（`nextTemp` 那一行是防止断链的全部）

> 对应程序：[LeetCode206_ReverseLinkedList.java](./LeetCode206_ReverseLinkedList.java)
> `main` 建了 `1..5` 并打印反转前后，实测：
>
> ```
> 反转前: 1 -> 2 -> 3 -> 4 -> 5
> 反转后: 5 -> 4 -> 3 -> 2 -> 1
> ```

---

## 一、三指针四步

```java
while (curr != null) {
    ListNode nextTemp = curr.next;   // ① 先存下一个，因为马上要改 curr.next
    curr.next = prev;                // ② 反向
    prev = curr;                     // ③ prev 前进
    curr = nextTemp;                 // ④ curr 前进
}
return prev;
```

**第一步不能省、也不能挪到第二步之后**：一旦执行了 `curr.next = prev`，原来的"下一个"就丢了，
再想 `curr = curr.next` 会走回已经反转的节点 —— 典型的"反转成环/只剩一个节点"的来源。
注释里那句 `nextTemp = 2 3 4 ...` 说的就是这个暂存动作。

循环结束时 `curr == null`、`prev` 指向原链表最后一个节点 —— 也就是新链表的头。

## 二、差分对拍

固定种子 20,000 组随机（长度 0..7、值随机），与"先把值抄进数组、倒序后再重建链表"的参考实现比：

```
   与数组反转的结果不同 —— 0 组
```

同时也间接排除了"反转成环"：比对时按值取前 20 个（n ≤ 7），如果出现环，取出来的序列会是重复值，
不可能等于倒序数组。

## 三、边界

```
   null        -> 返回 null（while 不进，prev 就是 null）
   单节点       -> 返回它自己（一次循环：next 置 null、prev=它、curr=null）
   两个节点     -> 正常反转
```

**没有递归版本**：递归写法更短，但在 LeetCode 上长链表会 `StackOverflowError`
（这题 n ≤ 5000，递归其实还撑得住；换成 10⁵ 就未必）。迭代版 `O(n)` 时间、`O(1)` 空间，是这题的标准答案。

## 四、和 234 的关系

`p234`（回文链表）里有一段一模一样的 `reverseList`，注释写着"这就是你刚学会的【反转链表】直接拿过来用"。
那边用它**只反转后半段**，比完再反转回来 —— 所以 206 是基础件，234 是它的一个应用。

值得注意：**两份代码各自定义了自己的 `ListNode`**（206/234 是三构造器版，160/141 是单构造器版），
靠不同包名共存。真要把它们抽成公共类，四个包里那四个 `ListNode` 就必须合并成一个 —— 现在能编过是因为**一题一包**。

## 五、复杂度的一句话解释

每个节点被访问常数次：`nextTemp` 读一次、`curr.next` 写一次、两个指针各前进一次。
所以时间 `O(n)`、空间 `O(1)`（只用了三个引用）。没有任何递归栈、没有额外容器 ——
这也是它比"用栈或者 ArrayList 倒着存"更好的地方。

## 六、一句话记住

```
   ①存 next → ②反向 → ③prev 前进 → ④curr 前进；第一步丢了，改完 next 就找不到后面了；
   20,000 组与"数组倒序重建"0 差异；null/单节点/两节点都对；
   迭代 O(n)/O(1)，递归版长链表会爆栈（这题 n<=5000 还撑得住）；
   234 里的 reverseList 就是这段代码，只是只反转后半段、并且比完要再反转回来。
```
