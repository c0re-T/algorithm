# LeetCode 34 在排序数组中查找元素的第一个和最后一个位置（两次二分，撞到也别停）

> 对应程序：[LeetCode34_FindFirstAndLastPositionOfElementInSortedArray.java](./LeetCode34_FindFirstAndLastPositionOfElementInSortedArray.java)
> `main` 传的是 `{5,7,7,8,8,10}` 找 8，实测：
>
> ```
> [3, 4]
> ```

---

## 一、两个独立二分，命中后继续往同侧收

```java
if (nums[mid] == target) {
    leftBound = mid;   // 先记下来
    rt = mid - 1;      // 但不停，继续向左找更早的
}
```

`searchLeft` 和 `searchRight` 各跑一遍，命中时**记录 + 继续收缩**，循环结束留下的就是边界。两处唯一的差别是记录后动哪一边：左边界 `rt = mid - 1`，右边界 `lt = mid + 1`。`searchRange` 里只要 `left == -1` 就直接返回 `{-1, -1}` —— 左边界都没找到，右边界不可能有。

## 二、穷举对拍

穷举 n=0..7、元素只取 0/1/2 的所有有序数组（3ⁿ 个），每个数组查目标 0..3：

```
穷举 13,120 组：与"线性扫一遍取首末"0 差异
随机 20,000 组（长度 0..24、值域 0..7）：0 差异
```

穷举集合里包含大量首尾都是目标的数组（比如排序后的 `{1,2,2,2,2}`），这些也全部 0 差异；数组没排序时见下一节。

## 三、它不检查数组是否有序

前提写在调用方身上。传乱序数组不会报错，会安静地给一个"像边界"的错答案：

| 输入（乱序） | 结果 | 真值 |
| --- | --- | --- |
| `{2,1,2}` 找 2 | `[2,2]` | `[0,2]` |
| `{2,2,1,2,2}` 找 2 | `[3,4]` | `[0,4]` |

## 四、边界与副作用

| 输入 | 结果 |
| --- | --- |
| `{}` | `[-1, -1]`（两个二分各自 `lt=0, rt=-1`，循环不进） |
| `{1}` 找 2 | `[-1, -1]` |
| `{5,7,7,8,8,10}` 找 6 | `[-1, -1]` |
| `null` | `NullPointerException: Cannot read the array length because "<parameter1>" is null` |

没命中时两次调用返回的是两个不同的数组对象（`miss-arrays-distinct-object=true`），不是共享常量；入参不被修改，同一数组连调两次结果一致。

## 五、代价：2 log n

n=1,000,000 的数组上跑 20 万次 `searchRange`，实测 **35 ms**。两个二分各 `ceil(log₂ n) = 20` 轮，常数很小。

## 六、一句话记住

```
   两次二分：命中后记录 mid，再分别向左右继续收，撞到不能 return；
   穷举 13,120 组 + 随机 20,000 组与线性扫描 0 差异；
   它不检查有序性：{2,1,2} 找 2 给 [2,2]（真值 [0,2]），{2,2,1,2,2} 给 [3,4]（真值 [0,4]）；
   空数组给 [-1,-1]，null NPE，未命中返回新数组、不是共享常量；
   n=10^6 上 20 万次调用 35 ms。
```
