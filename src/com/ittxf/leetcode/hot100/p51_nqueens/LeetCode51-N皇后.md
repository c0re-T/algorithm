# LeetCode 51 N 皇后（回溯：按行放，冲突只查前面）

> 对应程序：[LeetCode51_NQueens.java](./LeetCode51_NQueens.java)
> `main` 跑 n=4，实测：
>
> ```
> [[.Q.., ...Q, Q..., ..Q.], [..Q., Q..., ...Q, .Q..]]
> ```

---

## 一、按行回溯，`isValid` 只跟已经放好的行比

```java
for (int col = 0; col < n; col++) {
    if (isValid(queens, row, col)) {
        queens[row] = col;
        backtrack(res, queens, n, row + 1);
    }
}
...
if (queens[i] == col || Math.abs(row - i) == Math.abs(col - queens[i])) return false;
```

外层 `for` 一行只放一个皇后，所以**行冲突天然不存在**；`isValid` 只检查 `i < row` 的列冲突和两条对角线（行差等于列差）。`queens[row]` 在递归前写入、回来不用清 —— 下一个 `col` 会直接覆盖它。深度只有 n 层，n=14 也不会碰栈。

`buildBoard` 每次都 `new` 一个 `ArrayList` 和 n 个字符串，所以结果之间互不共享。

## 二、解数对得上，顺序是"第一行皇后列号升序"

n=0..12 实测（括号里是原版的耗时）：

| n | 解数 | n | 解数 |
| --- | --- | --- | --- |
| 0 | 1 | 7 | 40 |
| 1 | 1 | 8 | 92（0 ms） |
| 2 | 0 | 9 | 352（1 ms） |
| 3 | 0 | 10 | 724（4 ms） |
| 4 | 2 | 11 | 2,680（17 ms） |
| 5 | 10 | 12 | 14,200（98 ms） |
| 6 | 4 | 13 | 73,712（528 ms） |

n=1..8 的**解集合**与"枚举列号的 n! 个排列再逐个验证"参考实现完全一致（`setEqual=true`，解数也相同）。输出顺序由 DFS 决定：n=4 的两块棋盘第一行的皇后分别在第 1、2 列，正好升序。

## 三、n=0 与 n=−1

```
n=0  -> size=1，内层 size=0，打印 [ [] ]
n=-1 -> NegativeArraySizeException: -1     （new int[n] 直接拦下）
```

n=0 时 `row == n` 在第一次调用就成立，于是"空棋盘"被当成一个解收进去。LeetCode 的 n ≥ 1，所以不触发；自己调用时别把 `[[]]` 当成"无解"。

## 四、规模：解数长得比指数还快，瓶颈是结果集

| n | 解数 | 原版耗时 | 布尔数组版耗时 |
| --- | --- | --- | --- |
| 12 | 14,200 | 90 ms | 45 ms |
| 13 | 73,712 | 528 ms | 253 ms |
| 14 | 365,596 | 3,304 ms | 1,586 ms |

布尔数组版（`col[]` / 两条对角线）只做同样的回溯，n=14 快 **2.08 倍**。原版 `isValid` 每次都往左扫一遍已放的行，n 大时这层 O(n) 开始显形。

n=15 时**只存棋盘就 OOM**：`-Xmx2g` 下实测 `OutOfMemoryError: Java heap space`，栈在 `buildBoard`。换成"只计数不建棋盘"的版本：

```
n=15 -> 2,279,184 个解，8,961 ms
n=16 -> 14,772,512 个解，60,427 ms
```

所以 n=15 的 2 GB 不是被递归吃掉的，是被**约 228 万个 `List<String>`** 吃掉的。题面 n ≤ 9。

## 五、一句话记住

```
   按行放皇后，外层 for 一行一个，isValid 只查 i < row 的列与两条对角线；
   n=0..12 解数 1,1,0,0,2,10,4,40,92,352,724,2680,14200，与 n! 排列参考的集合全等；
   n=0 返回 [[]]（一个空棋盘解），n=-1 抛 NegativeArraySizeException；
   n=14 原版 3,304 ms、布尔数组版 1,586 ms（2.08 倍）；
   n=15 只存棋盘在 2 GB 下 OOM，改计数版 2,279,184 个解 / 8.96 s，n=16 是 14,772,512 / 60.4 s；
   递归深度只有 n，爆的不是栈，是结果集。
```
