# LeetCode 73 矩阵置零（先记录、再统一抹零，别边扫边改）

> 对应程序：[LeetCode73_SetMatrixZeroes.java](./LeetCode73_SetMatrixZeroes.java)
> `main` 用 `{{0,1,2,0},{3,4,5,2},{1,3,1,5}}`，实测输出
> `[[0, 0, 0, 0], [0, 4, 5, 0], [0, 3, 1, 0]]`。

---

## 一、为什么必须"两趟"

最直观的写法是边扫边把行列置零，但那样**新置的零会被当成"原本就是零"**，继续扩散到整张矩阵。
所以正确顺序只有一种：

```
   第一趟：只记录哪一行、哪一列需要置零（不修改矩阵）
   第二趟：按记录统一置零
```

这也是所有"原地标记"题的通则（和 `p41` 的"先归位再扫"、`p289` 生命游戏的"先记录再更新"同源）。

## 二、他的实现：`O(m + n)` 的布尔数组

```java
boolean[] row = new boolean[m];
boolean[] col = new boolean[n];
for (...) if (matrix[i][j] == 0) { row[i] = true; col[j] = true; }
for (...) if (row[i] || col[j]) matrix[i][j] = 0;
```

清楚、无坑，代价是 `O(m+n)` 额外空间。题面的进阶要求是 `O(1)`：
用**第一行和第一列**当标记位（它们本来就要不要置零，先单独记下来）。
那份写法的经典 bug 是"先处理第一行/列标记，再用它去抹零"导致第一行自己被反复污染 —— 他这里选了简单版，躲开了。

## 三、差分对拍

固定种子 20,000 组随机（行 1..4、列 1..4、值域 0..3，约 1/4 是 0）：

```
   与"另开 Set 记录行号列号再抹零"的参考实现不同 —— 0 组
```

单行、单列、全零、含多个零的情况都覆盖到了。举两个手算：

```
   [[0]]           -> [[0]]
   [[1,0,3]]       -> [[0,0,0]]        （一行里有一个零 → 整行抹零）
   [[1],[0],[3]]   -> [[0],[0],[0]]    （一列同理）
```

## 四、边界

```
   空矩阵 new int[][]{}  -> ArrayIndexOutOfBoundsException
```

因为第一行就写 `int n = matrix[0].length;`（假设至少有一行）。题面保证 `m, n >= 1`，所以交上去没事。
真正的"空"在 Java 里还有两种形态，行为不同：

```
   new int[0][]   -> matrix[0] 越界（他的写法崩在这里）
   new int[1][0]  -> n = 0，两个循环都不进，返回原样（不崩）
```

第二种其实值得注意：一行零列时方法"什么都不做"是对的，但它的正确性来自循环边界而不是设计。

## 五、和 54/48/240 的关系

这四道矩阵题看着像，处理的维度完全不同：

| 题 | 在动什么 | 额外空间 |
| --- | --- | --- |
| 73 矩阵置零 | 按行列传播标记 | `O(m+n)`（进阶 `O(1)`） |
| 48 旋转图像 | 转置 + 行反转（只对方阵） | `O(1)` |
| 54 螺旋矩阵 | 四条边界向里收缩 | `O(1)`（输出不算） |
| 240 搜索二维矩阵 | 从左下角"阶梯"走 | `O(1)` |

**共同点只有一条：先把矩阵的形状（行数、列数、是否方阵）搞清楚**，因为四份代码里 `matrix[0].length` 都是硬取的。

## 六、一句话记住

```
   先记录、再统一抹零 —— 边扫边改会把新零当成原有零，扩散到整张矩阵；
   他的版本用 O(m+n) 的布尔数组，清楚但不符合题面的 O(1) 进阶；
   20,000 组与 Set 参考 0 差异；单行/单列/全零都覆盖到了；
   空矩阵 new int[][]{} 会 AIOOBE（matrix[0].length），而 new int[1][0] 因为列数为 0 反而不崩。
```
