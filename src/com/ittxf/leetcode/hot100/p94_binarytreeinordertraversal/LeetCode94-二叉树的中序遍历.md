# LeetCode 94 二叉树的中序遍历（递归本身没错，错在 `list` 是实例字段）

> 对应程序：[LeetCode94_BinaryTreeInorderTraversal.java](./LeetCode94_BinaryTreeInorderTraversal.java)
> `main` 连跑三棵树，实测输出：
>
> ```
> 空树: []
> 示例树中序遍历: [1, 3, 2]
> 完美二叉树中序遍历: [1, 3, 2, 4, 2, 5, 1, 6, 3, 7]
> ```
>
> 第三行注释写的是"期待输出 `[4, 2, 5, 1, 6, 3, 7]`"——实际多了前一次调用的 3 个值。

---

## 一、递归顺序

```java
if (root == null) return list;
if (root.left != null) inorderTraversal(root.left);
list.add(root.val);
if (root.right != null) inorderTraversal(root.right);
return list;
```

中序 = 左 → 根 → 右。对 `1 -> 右 2 -> 左 3` 这棵树：

```
    1
     \
      2
     /
    3
```

先走左（空），加 1；再走右子树：先走 2 的左子树加 3，再加 2 → `[1, 3, 2]`。

`if (root.left != null)` 是多余的（下一层开头已经挡了 null），但不影响结果。

## 二、真正的问题：`List<Integer> list` 写在了字段上

```java
class Solution {
    List<Integer> list = new ArrayList<>();   // 整个 Solution 实例共用这一份
    public List<Integer> inorderTraversal(TreeNode root) { ... }
}
```

`Solution` 对象活多久，这个 `list` 就活多久；每次调用都往同一份里 `add`，而且**返回的也是同一个对象**。实测：

```
第 1 次(空树) = [1, 3, 2, 4, 2, 5, 1, 6, 3, 7]
第 2 次(示例树) = [1, 3, 2, 4, 2, 5, 1, 6, 3, 7]
第 3 次(7 节点满树) = [1, 3, 2, 4, 2, 5, 1, 6, 3, 7]
三次返回的是同一个 List 对象: a==b true, b==c true
```

三次的返回值引用完全相同，所以"第 1 次的结果"会随着后两次调用一起变长。`main` 里逐次打印，看到的是：

| 调用 | 当时的 list | 是否正确 |
| --- | --- | --- |
| 空树 | `[]` | ✓ |
| 示例树 | `[1, 3, 2]` | ✓ |
| 7 节点满树 | `[1, 3, 2, 4, 2, 5, 1, 6, 3, 7]` | ✗（应为 `[4,2,5,1,6,3,7]`） |

同一棵树连续遍历两次，第二次直接翻倍：

```
[2, 1, 3] -> [2, 1, 3, 2, 1, 3]
```

每次 `new Solution()` 就正常：

```
[] / [1, 3, 2] / [4, 2, 5, 1, 6, 3, 7]
```

**根因不在递归，而在"把一次调用的中间结果挂到对象状态上"。** 正确写法是方法内 `List<Integer> list = new ArrayList<>();`，再写一个私有 `void dfs(TreeNode node, List<Integer> list)` 把这份局部表传下去（LeetCode 每次调用都会 new 一个 `Solution`，所以字段版在判题机上能过，但一旦复用实例就错）。

## 三、递归深度

右斜链（每个节点只有右孩子）实测：

| 深度 | 结果 |
| --- | --- |
| 5,000 | 正常返回，0.1 ms |
| 10,000 | 首次运行 `StackOverflowError` |
| 10,000（JIT 预热后再跑） | 正常返回，0.1 ms |
| 20,000 / 50,000 / 100,000 | `StackOverflowError` |

阈值不是固定的：解释执行时的栈帧比 JIT 编译后大，**同一深度可能"第一次爆、热身后不爆"**。工程上遇到深树要么加大 `-Xss`，要么改用显式栈迭代。

## 四、代价

每个节点恰好访问一次：`O(n)` 时间；递归栈 `O(h)`（h 是树高），结果本身 `O(n)`。满树 100 万节点深度只有 20，不会触发栈问题；斜链才是风险。

## 五、一句话记住

```
   中序 = 左 → 根 → 右，递归三行；
   但 list 不能写在字段上：同一实例的每次调用共用一份，返回的也是同一个对象，
   main 第三行因此打印出 10 个值（上一次的 [1,3,2] 还在里面）；
   字段版在 LeetCode（每次 new Solution）能过，复用实例必错；
   深链 5,000 层安全，10,000 层冷启动爆栈、JIT 后又能过 —— 阈值随编译状态变。
```
