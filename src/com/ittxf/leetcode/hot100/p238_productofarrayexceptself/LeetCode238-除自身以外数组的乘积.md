# LeetCode 238 除自身以外数组的乘积（前缀积 × 后缀积，不用除法）

> 对应程序：[LeetCode238_ProductOfArrayExceptSelf.java](./LeetCode238_ProductOfArrayExceptSelf.java)
> `main` 用 `[1,2,3,4]`，实测输出 `[24, 12, 8, 6]`。要求 `O(n)` 且不能用除法。

---

## 一、两趟扫描

```java
int leftProduct = 1;
for (int i = 0; i < n; i++) { result[i] = leftProduct; leftProduct *= nums[i]; }   // result[i] = i 左边所有数的积

int rightProduct = 1;
for (int i = n - 1; i >= 0; i--) { result[i] *= rightProduct; rightProduct *= nums[i]; }  // 再乘上 i 右边所有数
```

`result[i]` 先被写成"左边的积"，再乘上"右边的积"，一次搞定。**`result` 既当输出又当临时变量**，
所以除了它之外只用了两个 `int` —— 这才是"`O(1)` 额外空间"的含义（输出数组不算）。

注释里那两行推演（`1 1 2 6` / `6 8 12 24`）和实测一致：

```
   第一趟 result = [1, 1, 2, 6]
   第二趟 result = [24, 12, 8, 6]
```

## 二、为什么不用除法

如果允许除法，"总乘积 / nums[i]"一行就完事，但**一旦有 0 就崩**：除以 0，或者所有 0 都被除没了。
这份实现不碰除法，所以含 0 的数组天然正确。实测：

```
   [0, 1, 2, 0] -> [0, 0, 0, 0]      ← 每个"除自身以外"的乘积里都还含另一个 0
   [0, 1, 2, 3] -> [6, 0, 0, 0]
```

## 三、差分对拍

固定种子 20,000 组随机（长度 1..8、值域 −3..3，约 1/7 是 0）：

```
   与"每格重算一遍"的暴力不同 —— 0 组
```

## 四、int 溢出：题面在帮你兜底

前缀积是连乘，很容易爆 `int`。实测把约束放大：

```
   [100000, 100000, 100000] -> [1410065408, 1410065408, 1410065408]
   真实值应为 10000000000，超出 int 范围，结果已经是错的
```

LeetCode 238 有一条额外约束：**"任意前缀或后缀的乘积保证在 32 位整数范围内"**，
所以用 `int` 是安全的。但这意味着：

- 如果题目放宽数值范围（比如 `nums[i] ≤ 10⁹`），这份代码会**静默溢出**，不会报错；
- 换成通用工具方法时，`leftProduct`/`rightProduct`/`result` 应改成 `long`。

这类"靠题面约束兜住溢出"的情况和 `p1` 的 `target - nums[i]`（只剩 7% 余量）、`p41` 的 `num ± 1` 是同一类账。

## 五、边界

```
   空数组  -> []            （两个循环都不进）
   单元素  -> [1]           （左边 1，右边 1，乘积 1）
   全 1    -> 全 1
   含 0    -> 见第二节，正确
```

## 六、和 53/560 的对照：三种"子数组/前缀"处理方式

| | 53 最大子数组和 | 238 除自身乘积 | 560 和为 K 的个数 |
| --- | --- | --- | --- |
| 用的是什么 | 一个滚动变量 | 两个方向的滚动积 | 一张前缀和哈希表 |
| 额外空间 | `O(1)` | `O(1)`（不算输出） | `O(n)` |
| 关键点 | 以 i 结尾的最优子结构 | 每个位置左右两侧的积互不依赖 | 计数需要历史 |

**"乘积"天然适合左右分治（前缀×后缀）**，因为乘法和交换律、结合律都成立、而且不需要"去掉自己"这种减法逆运算；
而"和"因为有负数，才需要哈希表记历史。

## 七、一句话记住

```
   result 先存左边的积、再乘右边的积，两趟 O(n)、除输出外 O(1) 空间；
   不用除法，所以含 0 的数组天然正确（[0,1,2,0] -> 全 0）；
   20,000 组与暴力 0 差异；int 溢出靠题面"任意前缀/后缀乘积在 32 位内"兜着，
   放宽约束时必须换 long —— 否则静默溢出（[100000]×3 实测 1410065408）。
```
